# 하강 (가제) — 설계 문서

> **v1.0** · 갱신 2026-08-02 · 상태: 경주 전환, 맵 재저작 중

최대 20인 경쟁 3D 1인칭. 지하 8층, 각 층의 한가운데에 아래로 떨어지는 투하구가 있다.
전원이 1층 외곽에서 동시에 출발해 여덟 번의 미로를 뚫고, 최하층 중심에 **먼저 닿은
한 명**이 이긴다. 괴물은 죽일 수 없고, 죽으면 그것으로 끝이다.

**변경 이력**
- **v1.0 — 4인 비대칭 협동 회수 → 20인 경쟁 하강 경주. 자세한 근거는

- v0.3 — 왕복 구조 · 시간 기반 위협 · 경제 시스템 · 맵 규칙
- v0.2 — 어그로 수치 · 상태 기계 · 진행도 위협 · 유령

> **v0.5에서 무엇이 살아남았나.** 거의 전부다. §05 이동 · §06 괴물 · §07 시간 위협

## 01. 개요와 한 판의 흐름

최대 20인 경쟁 호러, **3D 1인칭**. 모두가 같은 것을 보고 같은 것을 듣는다.
다른 것은 출발 장비뿐이다. 정보 비대칭이 아니라 **접근권 비대칭**이다.

### 핵심 루프

```
B1 외곽 (20명 동시 출발)
   │  미로를 뚫고 중심으로
   ▼
B1 중심 투하구  ──낙하──►  B2 외곽
   │
   ▼          … 여덟 층 반복 …
   ▼
B8 중심 = 도착점.  먼저 닿은 한 명이 이긴다.
```

**층마다 외곽에서 중심으로.** 투하구는 언제나 중심에 있고, 떨어지면 언제나 다음 층
*외곽*에 선다. 그래서 층을 내려갈 때마다 미로를 처음부터 다시 푼다 — 여덟 번.

### 착지가 외곽인 이유

투하구가 중심에 있는데 착지도 중심이면, 한 번 중심에 닿은 사람은 그대로 여덟 층을
떨어져 끝난다. 미로가 한 번뿐인 게임이 된다. 착지점을 외곽으로 보내야 **각 층이 독립된
미로**가 되고, 그때 비로소 "미로 탈출을 여덟 번"이라는 형태가 성립한다.

중심의 투하구는 층마다 **2~3개**다. 어느 것으로 뛰어내리느냐가 아래층 어디에서
시작하느냐를 정한다 — 무작위가 아니라 고정된 대응이므로, 맵을 아는 사람이 유리하다.
그것이 이 게임의 실력이다.

### 한 판의 흐름 (12~20분)

```
출발     20명이 B1 외곽 고리에 흩어져 선다. 밝고, 넓고, 안전하다.
        전원이 동시에 안쪽으로 움직인다.

초반     외곽→중간 관문 4개에 20명이 몰린다. 여기서 첫 순위가 갈린다.
        문을 닫고 가는 사람이 나온다.

중반     중간→안쪽 관문 2개. 괴물의 순찰 반경이 시작되는 곳.
        선두는 위험을 통과하고, 안전하게 간 사람은 뒤처진다.

후반     안쪽→중심 관문 1개. 그 층 전원이 같은 한 칸을 지난다.
        §07이 올라가 있어 늦은 사람일수록 괴물이 빠르다.

도착     B8 중심. 한 명.
```

### 장르적 결정 세 가지

**살상 수단이 없다**
- 괴물을 죽일 수 없다
- 저지는 전부 일시적 (섬광 · 문)
- 이길 수 없는 적 → 공포가 유지된다

**플레이어끼리도 죽일 수 없다**
- 방해 수단은 **문**과 **괴물을 남에게 떠넘기는 것**뿐이다
- 직접 타격이 없으므로 20명이 서로를 때려눕히는 난투가 되지 않는다
- 경주의 무기는 폭력이 아니라 **지형**이다

**죽으면 끝이다**
- 부활이 없다. 팀이 없으니 도와줄 사람도 없다
- 탈락자는 §09의 유령이 되어 남은 경주를 본다
- 그래서 협동판보다 괴물이 더 무섭다

## 02. 승패 조건

| 결과 | 조건 |
|---|---|
| **승리** | B8 중심 도착점에 **가장 먼저** 닿는다. 한 명뿐이다 |
| **완주** | 도착점에 닿았으나 1등이 아니다 — 순위가 기록된다 |
| **탈락** | 괴물에게 잡힌다. 유령이 되어 남은 경주를 본다 |
| **시간 초과** | 아무도 도착하지 않고 §07이 마지막 단계를 지난다 — 전원 패배 |

> **핵심: 이기는 방법은 하나뿐이고, 지는 방법은 여러 가지다.**
>
> 1등이 아니어도 완주 순위는 남는다. 그래서 선두를 놓친 사람에게도 계속 달릴 이유가
> 있고, 마지막 한 층에서 3등이 2등을 문으로 막는 일이 벌어진다.
>
> 시간 초과가 존재하는 이유는 §07 때문이다. 전원이 안전하게만 움직이면 괴물이
> 5.2 m/s가 되고 아무도 안쪽 고리를 통과하지 못한다. **누군가는 위험을 감수해야
> 판이 끝난다.**

### 순위 판정은 호스트가 한다

§13의 호스트 권한 원칙 그대로다. 도착 판정을 클라이언트가 내리면 경주 게임에서
가장 먼저 조작되는 값이 된다.

## 03. 어둠과 시야 — 안쪽으로 갈수록 보이지 않는다

> v0.5의 §03은 「목표 구조 — 3층위와 왕복」이었다. 단서로 목표물 위치를 좁히는
> 구조는 목적지가 처음부터 알려진 경주에서 성립하지 않아 통째로 걷어냈다.
> 어둠 규칙만 남기고, 그것을 **고리에 건다**.

### 고리별 조명

| 고리 | 조명 | 손전등 | 의미 |
|---|---|---|---|
| **외곽** | 상시 켜짐 | 필요 없음 | 20명이 서로를 본다. 출발선 |
| **중간** | 꺼져 있음 | 필요 | 배터리를 쓰기 시작한다 |
| **안쪽** | 없음 | 필수 | 손전등 사거리 바깥은 존재하지 않는다 |
| **중심** | 투하구만 빛난다 | — | 목적지는 멀리서도 보인다 |

**목적지가 보인다는 것이 중요하다.** 중심의 투하구는 안쪽 고리 어디서든 보이는
빛이다. 길을 잃는 것이 아니라 **가는 길이 막혀 있는 것**이 이 미로의 어려움이다.
보이는데 못 가는 것이 안 보여서 못 가는 것보다 훨씬 분하다.

### 배터리

§08에서 살아남은 유일한 것이다. 배터리는 판당 정해진 양이고 보충이 없다.
안쪽 고리에서 헤매면 그만큼 탄다. **빠른 길이 곧 절약**이라는 압박이 순위와 자원을
하나로 묶는다.

## 04. 직업 — 삭제됨. 전원 동일하다

> **v1.0에서 다섯 직업을 전부 걷어냈다.** 청음사 · 관측자 · 주자 · 정비공 · 섬광수는
> 4인이 서로를 메우는 구조였고, 20인 경주에는 메울 팀이 없다.

**20명이 완전히 같은 몸으로 출발한다.** 같은 속도, 같은 손전등, 같은 손.
차이를 만드는 것은 장비가 아니라 **길을 아는가**와 **어디까지 감수하는가**다.

### 왜 능력을 나눠 주지 않는가

능력을 나눠 주면 경주의 결과가 **픽으로 설명된다.** 진 사람은 자기가 진 이유를
자기 선택이 아니라 자기 픽에서 찾고, 그러면 다음 판에 고칠 것이 없다. 20명이 같은
출발선에 서면 1등과 20등 사이의 차이는 전부 그 판에서 한 행동이다.

또 하나. 픽이 있으면 **최적 픽이 생긴다.** 20명 중 열여덟이 같은 것을 고르는 순간
선택은 사라지고 밸런싱만 남는다. 없애는 것이 균형을 맞추는 것보다 확실하다.

### 전원이 가진 것

| | |
|---|---|
| **손전등** | 배터리 유한, 보충 없음 (§03) |
| **문** | 누구나 닫고 연다. 1.1초 · 부서지면 안 돌아온다 (§12-B) |
| **질주** | 5.6 m/s, **체력 제한.** 아래 |
| **귀** | 발소리는 누구에게나 들린다. 바닥 재질에 따라 다르게 (§12) |

### 질주는 남는다 — 전원에게, 체력으로

v0.5에서 5.6 m/s는 주자 전용이었다. 직업이 없어졌으니 **전원에게 준다.**
대신 무한하지 않다: 체력이 있고, 다 쓰면 걷는 속도까지 떨어지고, 서서 회복한다.

이 숫자가 남아야 하는 이유는 §06에 있다. 괴물의 덮치기는 **달리는 사람(4.5)은 잡고
질주하는 사람(5.6)은 놓치도록** 맞춰져 있다. 질주를 없애면 괴물에게 걸린 순간
누구도 살 수 없고, 그러면 §12의 시야 차단 지형이 통째로 무의미해진다.

질주가 유한하다는 것이 경주의 핵심 결정을 만든다:

> **지금 쓸까, 관문에서 쓸까.**
>
> 초반에 태우면 앞서지만 마지막 관문 하나를 스무 명과 함께 통과할 때 아무것도 없다.
> 아껴 두면 그 관문에 늦게 도착한다.

## 05. 조작과 이동

### 기본 조작 — 표준 FPS

| 입력 | 동작 |
|---|---|
| `마우스` | 시점 회전 (yaw + pitch) — **이것이 "앞"을 정의한다** |
| `W` / `S` | 시점 기준 전진 / 후진 |
| `A` / `D` | 좌우 스트레이프 |
| `Shift` | 달리기 · 계속 누르면 질주 (체력 소모) |
| `F` | 손전등 on/off |

**마우스 방향 = 이동 방향.** 뒤를 보려고 마우스를 돌리면 이동 기준도 함께 돌아간다.

### 속도 배율표 ← 추격의 문법

| 입력 | 방향 | 배율 | 질주 시 | 괴물(4.8) 대비 |
|:--:|---|:--:|:--:|---|
| `W` | 전진 | 100% | **5.6** | **+0.8** 벌어짐 |
| `W+A/D` | 대각 | 95% | 5.32 | +0.52 벌어짐 |
| `A/D` | 측면 | 90% | 5.04 | +0.24 벌어짐 |
| **`S`** | **후진** | **65%** | **3.64** | **−1.16 좁혀짐** |

> **핵심 결론: 뒷걸음은 괴물보다 느리다. 뒤를 보면 잡힌다.**
>
> 추격 중 거리를 확인하려면 뒤를 봐야 하고, 뒤를 보면 느려진다.
> §10 원리의 가장 직접적인 구현이며, 페널티가 애매한 서술이 아니라
> **거리 손실이라는 수치**로 확정된다.

### 45도 곁눈질 = 숙련 기술

```
정면 도주       속도 100%,  괴물 안 보임
45도 곁눈질     속도  95%,  괴물이 시야 끝에 걸림   ← 숙련
90도 측면       속도  90%,  괴물이 거의 정면
완전히 뒤       속도  65%,  잡힌다
```

플레이어가 **정보량과 속도를 연속적으로 조절**할 수 있다.
이산적 선택이 아니라 **아날로그 조절**이라는 점이 중요하다 — 마우스를 몇 도 돌릴지가 곧 실력이다.

| 숙련도 | 플레이 |
|---|---|
| 초보 | 앞만 보다 해제 타이밍을 놓치거나, 뒤를 봐서 잡힌다 |
| **숙련** | **45도로 곁눈질하며 거리를 관리하고** 정확한 순간에 시야를 끊는다 |

### FOV — 밸런스 항목이다

| FOV | 효과 |
|:--:|---|
| 60~70 | 호러 정석. 답답함 최대. **곁눈질이 거의 안 됨** |
| **75~85** | ✅ 곁눈질이 성립하면서 시야는 여전히 좁다 |
| 95+ | 곁눈질이 너무 쉬워 딜레마가 약화된다 |

**기본 80, 조절 범위 70~90.** 고정하면 멀미 민원이 발생하고,
무제한으로 열면 넓게 설정한 쪽이 유리해진다. 범위 제한이 절충점이다.

### 손전등이 포인터가 된다

> 근접 음성(§13)과 결합하면 *"저기! 저기 봐!"* + 손전등으로 비추는 동작이
> **말과 빛으로 동시에 위치를 전달**한다.
> §03의 "말로 전달해야 한다" 제약을 보조하는 비언어 채널이다.
>
> 따라서 **카메라 회전을 네트워크로 동기화해야 한다** — 남의 손전등 방향이 정보다.

### 조작 규칙 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 무언가를 읽는 동안 | **이동만 정지**, 마우스룩 허용 | 화면이 얼면 조작감 최악. 발이 묶인 채 둘러보는 게 더 무섭다 |
| 달리며 뒤 보기 | **자유롭게 허용** | 속도 손실이 페널티. 벽 충돌은 콘텐츠 |
| 목표물 운반 중 | 마우스룩 가능, **손전등 불가** | 돌아보긴 하는데 아무것도 안 보인다 |
| 소리의 방향 판별 | **몸을 돌려 삼각측량** | 3D 오디오는 카메라 기준 → **헤드폰 필수** |

### 네트워크 동기화 항목

| 항목 | 이유 |
|---|---|
| 위치 | 기본 |
| **카메라 회전 (yaw + pitch)** | **손전등 방향 = 정보.** pitch까지 필요 — 바닥·천장을 비추는 것도 신호 |
| 손전등 on/off | 괴물 인지에 영향 |
| 운반 상태 | 애니메이션 + 속도 |
| 스태미나 | 본인만 정확히, 남은 대략 |

> **에셋 비용 — 정정**
>
> **1인칭이어도 캐릭터 모델이 필요하다.** 협동 게임에서는 다른 3명이 보여야 한다.
> 필요한 것은 **플레이어 모델 20종**(시드 기반 실루엣 변주 — §04에 직업이 없으므로
> 색이 아니라 몸이 달라야 구분된다) +
> **애니메이션 4종**(서기 / 걷기 / 달리기 / 운반) + 손전등 부착.
>
> 완화 요인: 어둡고 1인칭이라 디테일 요구가 낮고, 자기 몸은 안 보이므로 손만 있으면 된다.
> 그래도 §16-1 리스크에 포함된다.

### §06 · §12 수치에 미치는 영향

```
기존 계산:  전진 100% 가정 → 초당 0.8m 벌어짐 → 12초에 9.6m
실제:      곁눈질 95%     → 초당 0.52m       → 12초에 6.2m
```

| 항목 | 기존 | 조정 |
|---|:--:|:--:|
| 질주 최대 이동 거리 | 67m | **60m** |
| 시야 차단 지점 간격 | 15~25m | 유지 (3~4회 기회) |

**어그로 해제가 계산보다 어려워진다.** 거리를 확인하면서 도망치면 덜 벌어지기 때문이다.
최적 플레이가 어려워야 실력 여지가 생기므로 이는 바람직한 방향이다.

## 06. 괴물 — 수치와 상태 기계

### 속도 관계 — 이 한 줄이 게임 전체를 정한다

```
걷기 2.0  <  달리기 4.5  <  괴물 4.8  <  질주 5.6   (m/s)
```

| 결과 | |
|---|---|
| 달리기로는 **도망칠 수 없다** | 시야를 끊거나 문을 닫아야 한다 (§12) |
| **질주만 도망칠 수 있다** | 유한한 체력이 경주의 핵심 결정이 된다 (§04) |
| 스태미나가 끝나면 잡힌다 | 무한 도주 방지 |

괴물이 달리기보다 **0.3만 빠른** 것이 핵심이다.
아주 조금 빠르면 **"거의 도망칠 수 있는데 안 되는"** 최악의 긴장이 생긴다.

> 위 값은 전진(100%) 기준이며 §05의 배율이 곱해진다. 괴물 속도는 시간대별로 변동한다(§07).

### 어그로 해제 — 거리만으로는 불가능하다

```
질주 5.6 − 괴물 4.8 = 초당 0.8m 벌어짐
스태미나 12초 × 0.8      = 최대 9.6m
해제 거리 12m            → 질주만으로는 절대 못 벌린다
```

> **어그로 해제는 거리가 아니라 맵을 쓰는 것이다.**
> 모퉁이를 돌고, 문을 닫고, 구조물을 끼고 돌아야 한다. §12 맵 설계 규칙의 근거.

| 파라미터 | 1차안 | 비고 |
|---|:--:|---|
| 해제 거리 | `12 m` | |
| 시야 차단 유지 | `3 초` | 단일 모퉁이로는 부족(§12) |
| 스태미나 (질주 지속) | `12 초` | 최대 이동 60m (§05 반영) |
| 스태미나 완전 회복 | `20 초` | |
| **해제 후 괴물 행동** | — | **마지막 목격 위치로 이동 → 수색** |

> **중요:** 어그로가 풀리면 괴물은 **마지막으로 본 위치**로 향한다.
> 따라서 남들이 있는 쪽에서 어그로를 끊으면 **괴물을 그들에게 배달하는 것**이 된다.
> 경주에서 이것은 실수가 아니라 **전술**이다.
> 도망치는 *방향*이 전략이 되는 지점이며, 거리 기반 해제 설계의 핵심 대가다.

#### 진짜 딜레마 — 질주를 언제 쓸 것인가

- 처음부터 질주 → 거리는 벌지만 차단 지점 도달 전에 소진
- 아껴두면 → 그 사이에 잡힐 수 있음

**맵을 알아야 최적화된다.** 실력이 개입하는 지점이고, 그래서 반복해도 재밌다.

### 상태 기계

| 상태 | 행동 | 소리 | 전이 조건 |
|---|---|:--:|---|
| **순찰** | 경로 이동 | 발소리 | 소리 감지 → 경계 |
| **경계** | 소리 방향으로 이동 | 발소리 | 시야 확보 → 추격 / 3초 무소득 → 순찰 |
| **추격** | 직진 | 발소리+포효 | 해제 조건 충족 → 수색 |
| **수색** | 마지막 위치 반경을 뒤짐 | 발소리 | 15초 무소득 → 순찰 |
| **정지** | 멈춰서 듣는다 | **없음** | 소리 감지 → 경계 / 5초 후 → 순찰 |

> **정지 상태가 이 게임의 무기**
>
> 괴물이 멈추면 **소리를 내지 않는다.** 그러면 **위치를 잃고**,
> 플레이어들은 *"어디 갔어? 방금 여기 있었는데"* 하게 되고, 방심하고 나오는 순간 걸린다.
>
> 순찰 중 랜덤하게(15~30초 간격) 정지를 넣는다. **침묵이 가장 무서운 소리다.**

## 07. 시간 = 위협도

> **시간이 유일한 통화다.**

모든 행동이 같은 자원을 쓰기 때문에 트레이드오프가 비교 가능해진다.

| 행동 | 비용 |
|---|:--:|
| 한 층 더 탐색 | ~3분 |
| 나가서 배터리 교체 | ~1분 |
| 전리품 하나 더 줍기 | ~40초 |
| 상점에서 고민 | ~30초 |
| 시각 확인하러 나가기 | ~1분 |

### 시간대별 위협 단계

| 경과 | 시각 | 속도 | 순찰 | 정지 | 추가 |
|:--:|---|:--:|---|:--:|---|
| 0~8분 | 초저녁 | 4.4 | 1개 구역 | 잦음 | — |
| 8~16분 | 밤 | 4.6 | 2개 구역 | 보통 | — |
| 16~24분 | 심야 | 4.8 | 절반 | 드묾 | **손전등 반경 −30%** |
| 24~32분 | 새벽 | 5.0 | 전체 | 없음 | **괴물이 출입구를 안다** |
| 32분+ | 동트기 전 | 5.2 | 전체 | 없음 | 생존 불가 수준 |

### 시각은 지상에서만 알 수 있다

안에서는 시간 감각이 없다. *"지금 몇 시쯤이야?"*를 알려면 나가야 하고, 나가는 데 시간이 든다.
이것이 또 하나의 왕복 이유가 되고, **회중시계 구매 동기**가 된다(§08).

### 왜 잠입 횟수 기반이 아니라 시간 기반인가

| 항목 | 잠입 횟수 기반 *(폐기)* | 시간 기반 *(채택)* |
|---|---|---|
| 나가서 쉬는 것 | 공짜 | **대가가 있다** |
| 압박 | 이산적 | **연속적** |
| 쇼핑 | 공짜 | **결정이 된다** |
| 구현 | 횟수 카운터 + 페널티 | **시계 하나** |

**시스템은 줄었는데 긴장은 늘었다.** 좋은 신호다.

## 09. 사망 처리 — 유령

| 항목 | 유령 상태 |
|---|---|
| 시야 | **맵 전체를 자유롭게 본다** (벽 통과) |
| 말하기 | **불가능** |
| 신호 | 근처 물건을 아주 약하게 흔든다 (쿨타임 45초) |
| 탈출 | **불가능** — 사망 페널티가 명확해진다 |

| 문제 | 해결 |
|---|---|
| 죽으면 지루하다 | 볼 게 있고 할 게 있다 |
| 죽은 사람이 정보를 주면 밸런스 붕괴 | **말할 수 없다** → 자유 정보 제공 불가 |
| 폐기한 영매 구조(§15) | **직업이 아니라 사망 후 상태로 재활용** |

영매가 직업으로 실패한 이유는 *"아무도 하고 싶어하지 않는다"*였다.
**벌칙 상태로 옮기면 그 문제가 사라진다** — 선택하는 게 아니니까.

> **최고의 순간**
>
> 산 자가 잘못된 길로 가고 있는데 유령은 정답을 안다. 그런데 **말할 수 없다.**
> 물건을 흔들어 신호를 보낸다. 쿨타임 45초 안에 다시 시도할 수 없다.
>
> *"방금 뭔가 흔들렸어?" / "바람이겠지" / (유령의 절규)*

## 10. 딜레마 지도

> **얻으려면 위험을 만들어야 한다.**

| 주체 | 얻는 것 | 대가 |
|---|---|---|
| 누구나 | 단서를 읽는다 | 위험 구역에 있어야 한다 |
| 누구나 | 손전등을 켠다 | 괴물이 본다 · 배터리를 쓴다 |
| 누구나 | 전리품을 챙긴다 | 시간을 쓰고 느려진다 |
| 누구나 | 목표물을 든다 | 손전등을 못 든다 · 질주 불가 |
| **도망 중** | **뒤를 봐서 거리를 확인한다** | **속도 65% → 거리가 좁혀진다** (§05) |
| 팀 전체 | 나가서 쉰다 · 구매한다 | 시간이 흐른다 |
| 조명 | 구역을 밝힌다 | 괴물이 그쪽으로 온다 |
| 문 | 경로를 차단한다 | 되돌아올 수도 없다 |
| 귀 | 소리를 듣는다 | 자기가 조용해야 한다 |
| 관측 | 괴물의 시야를 본다 | 그동안 남들이 앞선다 |
| 질주 | 관문을 뚫는다 | 다음 관문에서 쓸 것이 없다 |
| **누구나** | **손전등을 끄고 다닌다 — 괴물에게 안 보인다 · 배터리를 아낀다** | **어둠이 고인다 → 「그늘」이 목소리를 12초 뺏고, 방금 읽은 것을 흐린다** (§10 · §03 · §13) |

**마지막 행이 이 표의 유일한 구멍을 메운다.** §03은 손전등을 *하나의 스위치에 목표와
위험이 같이 걸린다*고 말하지만, 값은 **켠 쪽에만** 매겨져 있었다 — 끄면 공짜였다.
그래서 최적 전략은 언제나 *꺼놓고 다니다가 읽을 때만 켜기*였고, 딜레마는 딜레마가
아니었다. 그늘은 스위치의 반대쪽 값이다. 어둠을 **치명적으로** 만들지 않고
**비싸게** 만든다 — 대가는 체력이 아니라 §03이 이미 희소하게 만들어 둔 것, 즉
**본 것을 남에게 전달하는 능력**이다.

| 그늘의 성질 | 값 | 무엇에 묶여 있나 |
|---|---|---|
| 가득 차는 시간 | 45 s | §12의 3회 횡단(37.5 s)보다 길고, 배터리 1셀(210 s)보다 짧다 |
| 빛으로 지우는 시간 | 15 s | 빛 1초가 어둠 3초를 산다 |
| 목소리를 잃는 시간 | 12 s | §06의 `SprintStaminaSeconds` — 질주 한 번 |
| 경고 시점 | 60 % | 남은 40 %(18 s)면 §12가 보장하는 엄폐까지 걸어간다 |
| 괴물 반경 안 | **없음** | `MonsterSightRange` 20 m — §01의 *이길 수 없는 적*은 끝까지 하나다 |

> **왜 두 번째 *추격자*가 아닌가.** 그늘에는 위치도, 경로도, 속도도 없다. 조건이지
> 적이 아니다. §01의 공포는 *이길 수 없는 적 하나*에서 나오고, 둘이 되면 공포가
> 두 배가 되는 게 아니라 **반이 된다** — 둘 다 모델링할 수 없게 된 플레이어는 둘 다
> 모델링하기를 그만둔다. 괴물이 보는 곳(20 m)에는 그늘이 아예 없다는 규칙이 이걸
> 구조적으로 보장하며, §06의 측정된 추격 수치가 그늘 도입 후에도 **소수점 하나까지
> 동일**하다는 것이 그 증거다(STATUS.md §1.3).

> 🔴 **구현 상태: 규칙과 표현은 있고, 판에는 없다.** 코어 규칙 25개 테스트와 PlayMode
> 5개 테스트, 모델·오디오·프리팹·촬영 리그가 전부 통과하지만 `PresenceField`를 돌리는
> 것이 아무것도 없다 — 즉 **위 표의 대가를 실제로 치른 플레이어는 아직 없다.**
> 남은 배선과 그것을 이번에 하지 않은 이유는 STATUS.md §1.11에 있다.

하나의 원리 위에 전부 올라가 있다. 덕분에 **튜토리얼이 한 줄로 끝나고**,
새 콘텐츠를 추가할 때 **채택 기준이 명확하다** — *"이 기능은 이득과 위험을 교환하는가?"*

## 11. 인원 구조 — 최대 20인

**2~20명.** 전원이 B1 외곽 고리에 균등 배치돼 동시에 출발한다.

| 인원 | 성격 |
|---|---|
| 2~4 | 넓다. 관문에서 마주치는 일이 드물고, 괴물이 유일한 압박 |
| 5~10 | 관문마다 한두 명과 겹친다. 문이 처음으로 의미를 갖는다 |
| **11~20** | **안쪽 관문 하나에 여럿이 몰린다.** 설계 기준 |

### 인원이 늘면 무엇이 달라지나

관문 수는 인원과 무관하게 고정이다 (외곽→중간 4, 중간→안쪽 2, 안쪽→중심 1).
그래서 **인원이 늘수록 병목이 심해진다** — 20명이면 마지막 관문 하나를 스무 명이
지나야 한다. 그것이 이 게임이 20인에서 가장 재미있는 이유다.

> **관문 수를 인원에 맞춰 늘리면 안 된다.**
>
> 늘리면 20인 판이 20개의 1인 판이 된다. 서로 만나지 않는 경주는 경주가 아니다.
> 붐비는 것이 설계이고, 붐비는 곳에서 문과 괴물이 의미를 갖는다.

### 20명이 전부 같다

§04를 보라 — 직업이 없다. 20명은 같은 속도와 같은 손전등으로 출발하고, 차이는
전부 그 판에서 한 행동이다.

그래서 **문이 그 판의 성격을 만든다.** 앞선 사람이 관문을 닫으면 뒤 전체가 그
4.5초를 나눠 낸다. 부서진 문은 돌아오지 않으므로, 뒤로 갈수록 층은 열려 있고 대신
괴물은 §07만큼 빨라져 있다.

### 탈락자

죽으면 §09의 유령이 되어 남은 경주를 본다. 살아 있는 사람에게 개입할 수 없다 —
경주에서 죽은 사람이 산 사람을 도우면 그건 팀이다.

## 12. 맵 설계 규칙

> **맵은 아트가 아니라 시스템이다.**
> §06의 수치가 맵의 **성립 조건**을 규정한다. 아래는 수치에서 역산한 규칙이다.

### 12-A. 방사 구조 — 층의 모양

한 층은 동심 3겹이다. 바깥에서 안으로만 간다.

```
   ┌─────────────────────────────────────┐
   │  외곽 고리        20명이 여기 선다   │
   │   ┌───────────────────────────┐     │
   │   │  중간 고리                │     │
   │   │   ┌───────────────┐       │     │
   │   │   │  안쪽 고리    │       │     │
   │   │   │    ┌─────┐    │       │     │
   │   │   │    │중심 │    │       │     │
   │   │   │    │투하 │    │       │     │
   │   │   │    └─────┘    │       │     │
   │   │   └───────────────┘       │     │
   │   └───────────────────────────┘     │
   └─────────────────────────────────────┘
```

| 경계 | 관문 수 | 이유 |
|---|:--:|---|
| 외곽 → 중간 | **4** | 20명이 네 갈래로 갈린다. 첫 순위가 여기서 난다 |
| 중간 → 안쪽 | **2** | 절반으로 좁힌다. 마주치면 피하기 어렵다 |
| 안쪽 → 중심 | **1** | **그 층 전원이 같은 한 칸을 지난다** |

**관문 수는 인원과 무관하게 고정이다.** §11을 보라 — 붐비는 것이 설계다.

### 12-B. 중심으로 가는 길이 어려운 네 가지 이유

거리로 어렵게 만들면 지루하고, **좁혀서** 어렵게 만들면 경주가 된다.

1. **관문이 줄어든다** — 4 → 2 → 1. 위 표
2. **관문마다 문이 있다** — 닫는 데 1.1초, 부수는 데 4.5초, **부서지면 안 돌아온다.**
   협동판에서 괴물을 막던 물건이 경주에서는 **뒤따라오는 사람**을 막는다
3. **괴물이 안쪽을 순찰한다** — §07의 순찰 반경을 고리 단위로 읽는다. 외곽은 안전하고
   중심은 위험하다. 1등을 하려면 위험을 지나야 한다
4. **안쪽일수록 어둡다** — §03. 목적지는 보이는데 가는 길이 안 보인다

### 12-C. 투하구

- 중심에 **2~3개**. 각각 아래층 외곽의 **정해진** 착지점으로 간다
- 무작위가 아니다 — 맵을 아는 사람이 유리해야 실력이 성립한다
- 낙하는 되돌릴 수 없다. 잘못 고르면 그 층을 한 바퀴 더 돈다
- B8의 중심은 투하구가 아니라 **도착점**이다

### 12-D. 새 검증 규칙

`MapValidator`가 층마다 확인한다.

| 규칙 | 밴드 | 이유 |
|---|---|---|
| `ring-gates` | 4 / 2 / 1 | 병목이 설계대로인가 |
| `centre-path` | 외곽에서 중심까지 최단 60~90 m | 짧으면 경주가 안 되고 길면 지루하다 |
| `centre-single-gate` | 안쪽→중심 관문이 **정확히 1개** | 마지막 병목이 진짜인가 |
| `chute-count` | 2~3 | 선택이 있는가 |
| `chute-landing` | 착지점이 전부 외곽 고리 안 | 미로를 건너뛰지 못하는가 |

### 12-E. v0.5에서 그대로 살아남은 규칙

미로가 미로이기 위한 규칙이므로 경주에서도 유효하다. 아래 12-1부터 그대로 읽는다.

- 20 m 직선 통로 상한 · S자 통로 · 순환로 · 막힌 길 20~25%
- 구역 대각선 30~40 m · 구역당 바닥 재질 1개 · 관측 지점 · 은폐 지점

### 12-1. 원래의 §12 — 괴물과 미로의 관계

### 가장 중요한 계산 — 단일 모퉁이는 실패한다

```
모퉁이 통과 시점의 거리 = D
괴물이 그 모퉁이에 도달하는 시간 = D / 4.8초
시야 차단 3초가 필요 → D ≥ 14.4m

질주로 벌 수 있는 거리 = (5.6 − 4.8) × 12초 = 9.6m  (전진 기준)
```

| 어그로 시작 거리 | 모퉁이 통과 시 거리 | 판정 |
|:--:|:--:|:--:|
| 3m | 12.6m | ❌ 실패 |
| 5m | 14.6m | ⚠️ 이론상 겨우 |
| **10m** | **19.6m** | ✅ 여유 |
| 15m | 24.6m | ✅ 안정 |

**결론 두 개.**
1. **멀리서 어그로가 붙어야 살아남는다.**
2. 단일 모퉁이에 의존하면 안 된다 — 안정적 해제에는 **연속 차단**이 필요하다.

### 연속 차단 구조 3종

#### ① S자 통로 ← 가장 확실

```
────┐
    │  ← 구간 L
    └────┐
         │  ← 구간 L
         └────

구간 L = 10m,  총 20m
통과 시간 = 20 / 4.8 = 4.2초  ≥  3초  ✅
```

**10m 구간 2개의 S자 통로 하나면 해제가 성립한다.** 이것이 맵의 기본 단위다.

#### ② 순환로
돌아서 반대편으로 나올 수 있는 구조. 괴물이 **어느 방향인지 추측해야** 한다.

#### ③ 분기
갈림길. 괴물이 잘못 고르면 완전히 놓치지만 확률적이라 신뢰도가 낮다 — 보조 수단으로만.

### 두 성격의 공간이 인접해야 한다

| 공간 | 역할 | 특성 |
|---|---|---|
| **개방 공간** | **멀리서 어그로를 건다** | 홀 · 마당 · 계단실. 시야 15~25m 확보 |
| **미로 공간** | **시야를 끊고 도망친다** | S자 통로 · 순환로 · 좁은 복도 |

```
[개방 공간] ──진입── [미로 공간]
   어그로 획득          어그로 해제
```

개방 공간만 있으면 도망칠 곳이 없고, 미로만 있으면 멀리서 어그로를 걸 수 없다.

### 수치 규칙

| 항목 | 규칙 | 근거 |
|---|:--:|---|
| 시야 차단 지점 간격 | `15~25m` | 질주 60m에 3~4번의 기회 |
| S자 통로 구간 | `10m × 2회 굽음` | 통과 4.2초 > 차단 3초 |
| 순환로 개수 | 구역당 1+, 전체 3+ | 트리 구조는 사형선고 |
| 막힌 길 비율 | `20~25%` | 적으면 맵 지식 무의미, 많으면 운에 죽음 |
| 막힌 길 보상 | 전리품 · 자재 | 위험을 감수할 이유 |
| 구역 개수 | `4~6` | 단서 + 목표물 후보 + 출구 |
| 구역 대각선 | `30~40m` | |
| 맵 전체 | `100 × 100m` | 한 층에서 고리 3겹을 관통 가능 |
| 구역 간 진입점 | `2~3` | §07 순찰 반경이 구역 단위로 성립해야 |
| **직선 통로 최대** | **`20m`** | **넘으면 쫓기는 사람이 죽는다** |

### 직업별 맵 요구조건

#### 소리 → 바닥 재질이 지도다

| 구역 | 바닥 | 발소리 |
|:--:|---|---|
| A | 나무 | 삐걱 |
| B | 타일 | 딱딱, 반향 |
| C | 자갈 | 부스럭 |
| D | 콘크리트 | 둔탁 |
| 계단 | 금속 | 울림 |

**구역별로 바닥 재질이 달라야 발소리로 위치를 판별할 수 있다.** 경주에서는 괴물뿐
아니라 **남들이 어느 관문에 몰려 있는지**를 이것으로 안다.
아트 결정이 아니라 **시스템 결정**이다. 재질 경계를 명확히 할 것.

#### 관측 지점
높이 차(2층 난간) · 창문 · 격자 등 **15m 거리에서 안전하게 괴물을 볼 수 있는 지점**을
**구역당 1~2개** 배치. 안쪽 고리를 들어가기 전에 안을 살필 수 있는 자리다.

#### 병목에 문
- 순환로의 목에 문 하나 → 잠그면 순환이 끊김 (전략적 선택)
- **구역당 잠글 수 있는 문 1~2개** — 많으면 선두가 층 전체를 봉쇄한다
- 전기 패널 구역당 1개

#### 좁은 공간
넓은 곳에서는 괴물이 우회한다. 미로 공간이 무대이므로 별도 요구조건은 없다.

### 단서 · 목표물 후보 지점 조건

| 조건 | 이유 |
|---|---|
| **탈출로 2개 이상** | 하나 막히면 다른 쪽 |
| 각 입구에서 내부가 안 보임 | 괴물이 지나가도 즉시 발각 안 됨 |
| 근처에 시야 차단 지점 | 발각되면 즉시 도망 가능 |
| 전기 패널 접근 가능 | 구역을 밝힐 수 있어야 |

**후보 지점을 구역당 3개씩** 만들어두고 그중 하나를 선택한다.
**모든 후보가** 위 조건을 만족해야 한다.

### 검증 체크리스트

- [ ] 20m 넘는 직선 통로가 없다
- [ ] 개방 공간이 최소 1개 있고, 미로 공간과 인접해 있다
- [ ] S자 통로(10m×2)가 구역당 최소 1개 있다
- [ ] 순환로가 맵 전체에 3개 이상 있다
- [ ] 막힌 길 비율이 20~25%이고, 각각 보상이 있다
- [ ] 구역별 바닥 재질이 다르고 경계가 명확하다
- [ ] 관측 지점이 구역당 1개 이상 있다
- [ ] 잠글 수 있는 문이 구역당 1~2개, 병목에 있다
- [ ] 단서·목표물 후보가 구역당 3개, 모두 탈출로 2개 이상
- [ ] 구역 간 진입점이 2~3개로 제한돼 있다
- [ ] 출입구 근처에 은폐 지점이 있다 (§07 새벽 단계 대응)

### 실전 검증 — 탈출 테스트

**맵의 임의 지점에서 어그로를 걸고, 해제할 수 있는가?** 10개 지점에서 시도한다.

| 성공률 | 판정 |
|:--:|---|
| 8/10 이상 | ⚠️ 너무 쉽다 — 시야 차단 지점을 줄인다 |
| **5~7/10** | ✅ **적정** |
| 3/10 이하 | ⚠️ 너무 어렵다 — S자 통로를 추가한다 |

### 첫 맵 스케치

```
        ┌──────────────┐
        │   B 타일      │  ← 개방 공간 (홀), 시야 20m
        │  [관측지점]    │
        └───┬──────┬───┘
      S자통로│      │순환로
        ┌───┴──┐ ┌─┴────┐
        │A 나무 │ │C 자갈 │
        │[단서] │ │[단서] │
        └───┬──┘ └──┬───┘
            │  [문]  │      ← 관문
        ┌───┴───────┴───┐
        │   D 콘크리트    │
        │   [출구]        │
        └────────────────┘
```

프로토타입은 **B + A + S자 통로**만 만들면 된다.

## 13. 인프라와 기술 스택

> **직접 띄울 서버가 0대. DB도 필요 없다. 월 고정비 0원, 초기 비용 $100.**
>
> 4인 P2P + 호스트 권한 구조에서는 "서버"가 곧 플레이어 PC이므로 Steam이 나머지를 전부 제공한다.

### Steam이 무료로 주는 것

| 기능 | Steamworks | 비용 |
|---|---|:--:|
| **P2P 네트워킹** | Steam Networking Sockets | 0 |
| **NAT 통과 + 릴레이** | Steam Datagram Relay (SDR) | 0 |
| 로비 / 친구 초대 | ISteamMatchmaking | 0 |
| **음성 캡처 + 코덱** | ISteamUser::GetVoice | 0 |
| 계정 / 신원 | Steam ID | 0 |
| 세이브 | Steam Cloud | 0 |
| 업적 · 통계 · 리더보드 | Steam Stats / Leaderboards | 0 |
| 배포 · 패치 | Depot upload (steamcmd) | 0 |

**릴레이가 무료인 것이 결정적이다.** NAT 뒤의 플레이어끼리 직접 연결이 안 될 때
트래픽을 중계해야 하는데, 직접 하면 대역폭 요금이 실제로 나간다.

따라서 **전용 서버 · 매칭 서버 · 릴레이 서버 · 계정 서버 · DB 전부 불필요하다.**

### DB가 필요할 것 같은 것들

| 필요해 보이는 것 | 실제 해법 | DB |
|---|---|:--:|
| 계정 · 프로필 | Steam ID | ❌ |
| 세이브 | Steam Cloud | ❌ |
| 리더보드 | Steam Leaderboards | ❌ |
| 매칭 · 방 목록 | Steam Lobbies | ❌ |
| 업적 · 통계 | Steam Stats | ❌ |
| **영구 진행도 · 인벤토리** | **없음 — §08에서 판 안에 완결됨** | ❌ |

마지막 항목이 중요하다. **§15에서 판 사이 메타 프로그레션을 폐기한 것이
인프라 이득으로 돌아온다.** 영구 진행도가 있으면 저장해야 하고, 저장하면 치팅 검증이
필요해지고, 그러면 진짜 서버가 필요해진다.

### 착각하기 쉬운 것들 — 이것도 서버 불필요

| 하고 싶은 것 | 방법 |
|---|---|
| 게임 내 공지 | Steam 뉴스 API, 또는 정적 JSON 파일 |
| 구버전 접속 차단 | Steam이 자동 업데이트를 강제 → 대부분 자동 해결 |
| 웹사이트 | **스팀 페이지가 랜딩.** 프레스킷만 정적 호스팅(무료) |
| 커뮤니티 | Discord — Discord가 호스팅 |
| 빌드 자동화 | GitHub Actions (선택). 초기엔 수동 `steamcmd` |

### 근접 음성 구현

```
① 마이크 캡처       →  ISteamUser::GetVoice()
② 압축 패킷 전송     →  Steam Networking (P2P)
③ 수신 후 압축해제   →  DecompressVoice()
④ 재생             →  송신자 캐릭터 위치의 3D 오디오 소스로
```

> **핵심 트릭: 음성을 3D 오디오 소스로 재생하면 근접 음성이 자동으로 된다.**
> 거리 계산 로직이 필요 없다. 엔진의 3D 오디오가 감쇠와 벽 차폐를 처리한다.

```
거리 > 30m  →  전송 자체를 중단
```

**전부 받아놓고 볼륨만 0으로 재생하면 클라이언트 조작으로 다 들린다.**
전송 단계에서 끊어야 한다 — 대역폭 절감보다 **도청 방지**가 본질이다.
대역폭은 압축 후 초당 2~8KB 수준으로 부담이 없다.

### 텔레메트리 — 3단계, DB 없음

§06 수치는 **실제 사람들 데이터 없이는 못 맞춘다.** 하지만 요구사항을 보면
`판 종료 시 요약 1건 전송 → 나중에 집계` 로, **append-only 로그**다.
트랜잭션 · 조인 · 인덱스 · 실시간 쿼리가 전부 불필요하다.

#### 1단계: Steam Stats만 (인프라 0)

통계 항목을 정의하면 Steam이 저장하고 글로벌 집계까지 해준다.
**분포가 필요하면 버킷 카운터를 만든다.**

```
aggro_duration_0_5s     : 카운터
aggro_duration_5_10s    : 카운터
aggro_duration_10_15s   : 카운터
aggro_duration_15s_plus : 카운터
```

**히스토그램이 Steam Stats만으로 나온다.** 같은 방식으로:

| 버킷 | 검증 대상 |
|---|---|
| 어그로 지속 시간 | §06 해제 거리 12m |
| 왕복 횟수 | §07 시간 곡선 |
| 후진(S) 사용 시간 비율 | §05 곁눈질 배율 65% |
| 직업별 선택 카운터 5개 | §11 필수 직업 검증 |
| 아이템별 구매 카운터 | §08 경제 밸런스 |
| 클리어 / 전멸 / 포기 | 전체 밸런스 |

**밸런싱에 필요한 거의 전부가 여기서 나온다.**

#### 2단계: 로그 파일 (세부 이벤트가 필요해지면)

사망 좌표처럼 세부 데이터가 필요해지면:

```
서버리스 함수 1개  →  오브젝트 스토리지에 JSONL append
                     (S3 / R2 / Blob)
```

**DB가 아니라 파일이 쌓인다.** 나중에 다운로드해서 로컬 DuckDB로 쿼리한다
(JSONL / Parquet 직접 읽기 가능). 스키마 · 마이그레이션 · 백업 · 커넥션 전부 없음.

#### 3단계: 분석 서비스 (규모가 커지면)

PostHog 등을 붙인다. 이때도 DB는 서비스가 관리하고 나는 이벤트만 쏜다.

> 익명 세션 ID만 쓴다. **개인정보는 수집하지 않는다.**

### 기술 스택 (Unity)

| 영역 | 선택 | 근거 |
|---|---|---|
| 엔진 | **Unity** | 네트워킹 + 3D 오디오 + Steam 연동 생태계가 가장 성숙 |
| 1인칭 컨트롤러 | Starter Assets 또는 직접 | 마우스룩은 스크립트 20줄 수준 |
| Steamworks | Steamworks.NET | 저수준 래퍼, 안정적, 무료 |
| 네트워킹 | **Mirror + FizzySteamworks** | 자료·커뮤니티 최다 — **막혔을 때 검색이 된다** |
| 대안 | FishNet + FishySteamworks | 성능·기능은 앞서지만 자료가 적다 |
| 오디오 | Unity 기본 → 필요시 FMOD | 발소리 방향 판별 가능 여부를 프로토타입에서 판정 |
| 개발용 App ID | `480` (Spacewar) | 심사 전에도 로비·P2P·음성 테스트 가능 |

성능 차이보다 **막혔을 때 답을 찾을 수 있는지**가 1인 개발에서 훨씬 중요하다.
4인 게임에서 성능 한계에 부딪힐 일은 없다.

### 아키텍처 — 호스트 권한

| 항목 | 결정 |
|---|---|
| 권한 모델 | **호스트 권한** — 괴물 AI를 호스트가 돌린다 |
| 치팅 방어 | 거의 불필요 (친구끼리 하는 PvE) |
| 호스트 이탈 | **세션 종료** — 마이그레이션 하지 않음 |
| **단서 내용 · 목표물 위치** | **호스트만 보유.** 클라이언트에 보내면 메모리에서 읽힌다 |

마지막 항목이 중요하다. 정답을 클라이언트에 전송하면
**§03의 "기억해서 말로 전달" 제약이 무너진다.**

### 인프라가 아니라 행정 — 세팅해야 할 것

| 항목 | 비고 |
|---|---|
| Steamworks 파트너 등록 | 사업자 정보 · 은행 계좌 |
| **App ID** | **$100** (매출 $1,000 초과 시 환급) |
| W-8BEN 제출 | 한미조세조약으로 원천징수 감면 |
| Depot 설정 + 업로드 | 초기엔 수동 `steamcmd`로 충분 |
| **상점 페이지 자산** | 캡슐 이미지 · 트레일러 · 스크린샷 — **시간이 꽤 든다** |
| 헤드폰 권장 표기 | §05 — 3D 오디오가 게임의 핵심 |

### 나중에 서버가 필요해질 수 있는 경우

| 상황 | 필요해지는 것 |
|---|---|
| 스팀 외 플랫폼 출시 (에픽 등) | 자체 매칭 · 음성 추상화 레이어 |
| 공개 매칭 (친구 아닌 사람과) | Steam Lobbies로 가능하나 신고 · 필터 시스템 |
| 커뮤니티 데디케이티드 서버 요구 | 전용 서버 빌드 |

전부 지금은 불필요하다. 다만 **음성 · 네트워킹을 인터페이스로 추상화**해두면
나중 확장 비용이 줄어든다. 코드 몇 줄 차이다.

| # | 내용 | Steam |
|:--:|---|:--:|
| 1 | 1인칭 컨트롤러 + **속도 배율(§05)** + 괴물 AI + 어그로 | — |
| 2 | Mirror 로컬 호스트 — 같은 PC 2인스턴스 | — |
| 3 | 프로토타입 검증 (음성은 **디스코드**) | — |
| 4 | Steam 트랜스포트 + 로비 + 친구 초대 | `480` |

| 6 | 텔레메트리 (Steam Stats) · 크래시 리포팅 | — |

> **경고: 7번을 늦추지 말 것.**
> 상점 페이지는 게임 완성 전에 올려서 위시리스트를 모으는 용도다.
> 출시일 알고리즘 노출이 여기 걸려 있고, 스팀에서 가장 흔한 실수다.

### 2주 프로토타입

**만들 것**
- 구역 3개 (수작업, §12 스케치의 B+A)
- **1인칭 이동 + 속도 배율표**
- 단서 2개 + 목표물 1개
- 질주 + 문
- 괴물 1마리, 어그로 + 상태 기계
- 시계 + 시간대별 위협 2단계
- 전리품 3종 + 무게 규칙
- 2인 로컬 (캐릭터는 **캡슐**)

**안 만들 것**
- 랜덤 생성
- 나머지 직업 3개
- 게임 내 음성
- 상점 (전리품만 확인)
- 캐릭터 모델 · 애니메이션
- 매칭 · 로비 · 세이브
- 아트 · 사운드 폴리시 · 유령 상태

### 검증 질문 — 이 다섯 개만

| # | 질문 | 실패 시 |
|:--:|---|---|
| 1 | **추격이 재밌는가?** (거리를 벌리는 순간이 짜릿한가) | §06 어그로 수치를 고친다 |
| 2 | **곁눈질 딜레마가 작동하는가?** (뒤를 볼지 고민하게 되는가) | §05 후진 배율(65%)을 조정 |
| 3 | **"지금 나갈까?" 갈등이 생기는가?** | §07 시간 곡선 · §08 전리품 가치 |
| 4 | **"6이었나 9였나" 대화가 나오는가?** | §03 단서 제약을 고친다 |
| 5 | **발소리의 방향·거리를 구별할 수 있는가?** | FMOD를 붙인다 |

> **우선순위:** 1·2번이 안 되면 나머지를 아무리 잘 만들어도 안 된다.
> **어그로 수치와 속도 배율에 게임이 걸려 있다.**
> 그리고 이건 문서로 정할 수 없고 직접 만져봐야 나온다.

## 15. 설계 이력

이 설계에 도달하기까지 버린 것들. 되돌아가지 않기 위해 기록한다.

| 폐기안 | 폐기 이유 |
|---|---|
| 런타임 LLM 활용 | 매절 판매 + 변동비 = 잘 팔릴수록 적자. 지연시간도 실시간 액션과 맞지 않음 |
| 영매 / 침식 구조 *(감각 비대칭)* | 화면이 검은 역할은 **아무도 하고 싶어하지 않는다.** 감각을 대칭으로, 능력만 비대칭으로. 단 §09에서 사망 상태로 회수됨 |
| 사수 (총기 직업) | 괴물을 죽일 수 있으면 공포가 사라진다. 저지는 전부 일시적이어야 함 |
| 해독가 (목표 전담) | 목표를 한 명이 담당하면 나머지는 호위병이 된다. 전원 공동 작업으로 |
| 의무병 / 서포터 | 필수인데 재미없는 역할. 회복은 **직업이 아니라 아이템**으로 |
| 시간 기반 어그로 해제 | 기다리는 것은 실력이 아니다. 거리 + 시야 차단으로 대체 |
| 적응형 보스 패턴 | 고무줄 효과로 실력 성장의 보상이 사라진다. 대신 랜덤화 + 시간 기반 위협(§07) |
| 의식 복원 (목표 구조) | **서사 장치라 반복하면 빨리 낡는다.** 왕복 + 목표물 회수로 대체 |
| 잠입 횟수 기반 위협도 | 나가서 쉬는 것이 공짜가 되고 인공적 카운터가 필요. **시간 기반이 더 단순하고 압박이 연속적** |
| "벽에 부딪힌다"는 뒤보기 페널티 | 애매한 서술. **후진 속도 65%라는 수치로 대체**(§05) |
| 전용 서버 / 자체 릴레이 | Steam SDR이 무료로 해준다. 1인 개발자가 감당할 영역이 아님 |
| **텔레메트리용 DB (Supabase 등)** | **append-only 로그에 DB는 과하다.** Steam Stats 버킷 → JSONL → 서비스 순으로 |
| 판 사이 메타 프로그레션 | 한 판 25~35분 안에 성장 곡선이 완결된다(§08). 나중에 추가 가능 |

> **설계 관통 원칙**
>
> **패턴은 학습하게 두고, 내용을 매번 바꾼다.**
> 구조를 배우는 것이 실력이고, 그 실력이 통하지 않게 만들면 게임이 죽는다.
> 공략을 막으려 하지 말고, **공략을 봐도 남에게 전이되지 않는 축**을 만들 것.

| 2 | **경제 가격표** — 전리품 가치 ↔ 아이템 가격 밸런스 | 🔴 최우선 |
| 3 | 섬광 효과 지속시간 · 쿨타임 | 🟡 중 |
| 4 | 질주 스태미나 총량과 회복 속도 | 🔴 상 |
| 5 | 배터리 지속 시간 (왕복 리듬을 결정) | 🟡 중 |
| 6 | 목표물의 형태 · 서사적 정체 | 🟢 하 |
| 7 | 맵 개수 (얼리 액세스 시 3개 권장) | 🟢 하 |
| 8 | 가격 (9,900~12,000원 권장) | 🟢 하 |
| — | ~~어그로 수치 · 조작과 속도 배율 · 관측자 조건 · 단서 구조 · 사망 처리 · 순찰 패턴 · 엔진 · 인프라 · 맵 규칙 · 목표 구조 · 시간 위협 · 경제 구조~~ | ✅ 완료 |

> **1번 리스크 — 범위가 늘었다**
>
> §05에서 확인된 대로 **1인칭이어도 캐릭터 모델이 필요하다** (협동이라 남이 보인다).
> 괴물 1종 + 플레이어 1종 + 애니메이션. 나머지는 1인칭 · 어둠 · 모듈러로 우회 가능하지만
> **이 둘은 우회가 안 된다.** 프로토타입에서는 캡슐로 대체하고
> **에셋스토어를 미리 조사해 둘 것.** 없으면 일정이 몇 달 늘어난다.

> **2번이 현재 병목**
>
> **전리품 가치와 아이템 가격의 비율**이 게임 템포를 결정한다.
> 너무 싸면 2차 잠입에 다 갖춰지고, 너무 비싸면 아무것도 못 산다.
> §08의 성장 곡선(*1차 0 → 후반 자원 풍족 · 시간 부족*)이 실제로 나오는지가 판정 기준이다.
