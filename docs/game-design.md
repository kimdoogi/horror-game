## 01. 개요와 한 판의 흐름

4인 협동 호러, **3D 1인칭**. 네 사람은 **같은 것을 보고 같은 것을 듣는다.**
다른 것은 능력뿐이다. 정보 비대칭이 아니라 **역할 비대칭**이다.

### 핵심 루프

```
지상(안전 · 상점) ⇄ 지하(위험 · 단서 · 전리품 · 목표물)

잠입 → 단서로 목표물 위치를 좁힌다 → 전리품을 챙긴다 → 귀환
     → 판매 · 구매 → 다시 잠입 → … → 목표물 회수 → 탈출
```

### 한 판의 흐름 (25~35분)

```
초저녁   맨몸으로 1차 잠입 → 단서 확보 + 전리품 조금
        귀환 → 전리품 판매 → 배터리 + 자재 구매

밤      2차 잠입 → 위치 좁히기 + 대형 전리품 발견
        "이거 들고 갈까? 2명 필요해"
        귀환 → 강화 손전등 구매

심야    3차 잠입 → 목표물 발견
        "지금 들고 나갈까, 전리품 더 챙길까?"   ← 판의 핵심 결정

새벽    호송 (목표물 1명 + 3명) → 괴물은 출입구를 안다
        탈출 or 전멸
```

### 장르적 결정 두 가지

**살상 수단이 없다**
- 괴물을 죽일 수 없다
- 저지는 전부 일시적 (섬광 · 문 · 함정)
- 이길 수 없는 적 → 공포가 유지된다

**전담 역할이 없다**
- 단서 풀이는 전원 공동 작업
- 직업은 생존이 아니라 *접근권*을 만든다
- 지갑도 공용 → 매번 협상

## 02. 승패 조건

| 결과 | 조건 |
|---|---|
| **완전 승리** | 목표물 회수 + 4인 전원 탈출 |
| **부분 승리** | 목표물 회수 + 일부 탈출 |
| **생존** | 목표물 없이 탈출 — 그 판의 정보는 남는다 |
| **패배** | 전멸 — **그 판의 모든 것을 잃는다** |

> **핵심: 누군가는 살아서 나가야 한다.**
>
> 한 명이라도 탈출하면 그 판에서 알아낸 정보가 보존된다.
> 전멸하면 전리품 · 크레딧 · 정보가 전부 사라진다.
> 이 비대칭이 *"지금 나갈까?"*를 진짜 갈등으로 만든다.

## 03. 목표 구조 — 3층위와 왕복

### 세 층위

| 층위 | 성격 | 필수 | 반출 |
|---|---|:--:|:--:|
| **단서** | 정보 — 목표물 위치를 좁힌다 | 필수 | ❌ |
| **목표물** | 판의 목적 | 필수 | ✅ |
| **부수 전리품** | **통화** (§08) | **선택** | ✅ |

**전리품이 선택적인 것이 핵심이다.** 안 챙겨도 클리어된다. 챙기면 강해진다.
*"목표물만 들고 빨리 나갈까, 전리품도 주울까?"* — 시간을 쓰면 위협이 올라간다(§07).
두 층위가 분리되므로 아래의 **단서 반출 금지**와 충돌하지 않는다.

### 왕복 구조 — 왜 한 번에 못 하나

| 소모 자원 | 소모 조건 | 보충 |
|---|---|---|
| **손전등 배터리** | 시간 경과 + 켤 때마다 | 지상 발전기 |
| 정비 자재 | 문 · 함정 · 차단물 설치 | 지상 차량 |
| 부상 | 잡혔다 탈출 시 (주자) | 지상에서만 |

**배터리가 떨어지면 단서를 읽을 수 없다.** 아래 "어둠 = 잠금장치"가 그대로 자원 압박으로
전환되므로 새 시스템이 필요 없다. 이것이 **나와야 하는 이유**와 **다시 들어가는 이유**를
동시에 답한다.

> **부분 리셋 규칙**
>
> 나가면 초기화되는 것: **괴물의 추격 상태 · 위치 · 어그로**
> 나가도 유지되는 것: **시간** (그리고 계속 흐른다)
>
> **나가는 것은 숨 돌리기이지 리셋이 아니다.**

### 단서가 위치를 좁히는 방식

```
1차 잠입에서 얻은 단서:  "그것은 물이 있는 층에 있다"
2차 잠입에서 얻은 단서:  "물이 있는 층은 지하 3층이다"
3차 잠입:                지하 3층으로 직행 → 회수
```

**몇 번 왕복해야 하는지 매판 다르다.** 운이 좋으면 2번, 나쁘면 5번.
이것이 랜덤성의 주 축이며 *"이번 판 운 없네"*라는 대화를 만든다.

### 핵심 제약 — 단서를 가지고 나올 수 없다

> **그 자리에서 보고, 기억해서, 말로 전달해야 한다.**

| 효과 | 설명 |
|---|---|
| 소통이 강제된다 | 스크린샷도, 아이템 전달도 없다 |
| 위험 구역에 들어가야 한다 | 안전한 곳에서 해결 불가 |
| **기억 오류가 발생한다** | *"6이었나 9였나…"* — 이 게임의 주된 웃음이자 사망 원인 |
| 재방문이 필요해진다 | 틀렸으면 다시 들어가야 한다 |

#### 혼동쌍 — 의도적으로 심는다

| 혼동쌍 | 발생 조건 |
|:--:|---|
| 6 ↔ 9 | 뒤집힌 각도에서 |
| 1 ↔ 7 | 손글씨체 |
| ㅁ ↔ ㅇ | 흐릿할 때 |
| 좌 ↔ 우 | 거울 · 반사면 |

여기에 **읽기 방해 요소**를 얹는다 — 손전등의 좁은 빛 · 낡아서 지워진 부분 ·
급하게 봐야 하는 상황.

### 어둠 = 목표의 잠금장치

| 조명 수단 | 특성 |
|---|---|
| **손전등** (전원 기본) | 빛이 좁다 · 오래 비춰야 읽힌다 · **괴물이 잘 본다** · 배터리 소모 |
| **구역 조명** (정비공) | 구역 전체가 밝다 · 여러 명이 동시에 읽는다 · **괴물도 그쪽으로 온다** |
| **조명탄** (구매) | 정비공 없이 구역을 밝힌다 · 1회용 · 소리를 낸다 |

목표와 위험이 **같은 스위치에 걸린다.**

### 목표물 운반

| 규칙 | 결과 |
|---|---|
| **양손을 쓴다** | 손전등을 들 수 없다 → **누군가 비춰줘야 한다** |
| 전리품 동시 소지 불가 | 전리품은 그 전에 다 챙겨야 한다 |
| 주자가 들면 질주 불가 | **누가 들 것인가**가 마지막 결정 |

마지막 왕복은 **목표물 1명 + 호송 3명** 구성이 된다.
운반자는 앞을 보지 못하므로 사실상 **2인 1조 호송**이다.

### 랜덤화 범위

| 요소 | 매판 | 이유 |
|---|:--:|---|
| 목표물 **위치** | 랜덤 | 왕복 횟수가 매판 달라진다 |
| 단서 위치 · 내용 | 랜덤 | 좌표 · 정답 공략 무력화 |
| 전리품 배치 | 랜덤 | 막힌 길에 좋은 것을 둔다(§12) |
| 맵 구조 · 단서 조합 방식 | **고정** | 학습 가능해야 실력이 성장한다 |

## 04. 5개 직업

전부 **강한 능력 + 명확한 제약** 구조. 각 직업은 생존뿐 아니라 **목표에도 관여**한다.

### 청음사

| | |
|---|---|
| 능력 | 소리로 괴물의 위치 · 거리 · 이동 방향을 파악 |
| 제약 | **자기가 소리를 내면 못 듣는다.** 뛰거나 문을 열면 정보가 끊긴다 |
| 목표 관여 | 진입 타이밍을 결정한다 |
| 맵 요구 | 구역별로 **바닥 재질이 달라야** 위치 판별이 가능(§12) |

### 관측자

| | |
|---|---|
| 능력 | 괴물의 시야를 본다 → **누가 표적인지** |
| 발동 | **괴물로부터 15m 이내 + 이동 정지 3초** (마우스룩은 허용, §05) |
| 지속 | 정지를 유지하는 동안만. 움직이면 끊긴다 |
| 특징 | 유일하게 **보호가 필요하고**, 유일하게 **아이템으로 대체 불가**(§11) |

### 주자

| | |
|---|---|
| 능력 | **질주 5.6 m/s** + 괴물의 어그로 강제 획득 |
| 해제 | 거리 **12m** 이상 + 시야 차단 **3초** 유지 |
| 제약 | 스태미나 12초. **어그로를 풀 지점을 골라야 한다** |
| 목표 관여 | 괴물을 끌어내 **진입 창**을 만든다 |

### 정비공

| | |
|---|---|
| 능력 | 문 잠금 · 구역 조명 · 소음 함정 · 차단물 설치 |
| 제약 | **시간과 자재.** 즉석 사용 불가 — 사전 준비형 |
| 목표 관여 | **조명으로 단서를 읽게 만든다** · 금고를 연다 |
| 특징 | **실수가 아군을 죽인다** (문 안에 아군 · 조명 끔 · 함정에 주자) |

### 섬광수

| | |
|---|---|
| 능력 | 괴물을 짧게 기절시킨다 |
| 제약 | 효과가 약하다. 대신 **재사용 가능** (쿨타임) |
| 목표 관여 | 단서를 읽는 사람 · 목표물 운반자를 보호한다 |

> **Design Note — 정비공은 팀에게 가장 위험한 아군이다.**
>
> 사고가 시스템에서 자동 생산되고, 그게 이 역할의 정체성이며 방송 콘텐츠의 핵심이다.
> 버그로 취급해 없애지 말 것.

## 05. 조작과 이동

### 기본 조작 — 표준 FPS

| 입력 | 동작 |
|---|---|
| `마우스` | 시점 회전 (yaw + pitch) — **이것이 "앞"을 정의한다** |
| `W` / `S` | 시점 기준 전진 / 후진 |
| `A` / `D` | 좌우 스트레이프 |
| `Shift` | 달리기 (주자는 질주) |
| `F` | 손전등 on/off |

**마우스 방향 = 이동 방향.** 뒤를 보려고 마우스를 돌리면 이동 기준도 함께 돌아간다.

### 속도 배율표 ← 추격의 문법

| 입력 | 방향 | 배율 | 주자 질주 시 | 괴물(4.8) 대비 |
|:--:|---|:--:|:--:|---|
| `W` | 전진 | 100% | **5.6** | **+0.8** 벌어짐 |
| `W+A/D` | 대각 | 95% | 5.32 | +0.52 벌어짐 |
| `A/D` | 측면 | 90% | 5.04 | +0.24 벌어짐 |
| **`S`** | **후진** | **65%** | **3.64** | **−1.16 좁혀짐** |

> **핵심 결론: 뒷걸음은 괴물보다 느리다. 뒤를 보면 잡힌다.**
>
> 추격 중 거리를 확인하려면 뒤를 봐야 하고, 뒤를 보면 느려진다.
> §10 원리의 가장 직접적인 구현이며, 페널티가 애매한 서술이 아니라
> **거리 손실이라는 수치**로 확정된다.

### 45도 곁눈질 = 숙련 기술

```
정면 도주       속도 100%,  괴물 안 보임
45도 곁눈질     속도  95%,  괴물이 시야 끝에 걸림   ← 숙련
90도 측면       속도  90%,  괴물이 거의 정면
완전히 뒤       속도  65%,  잡힌다
```

플레이어가 **정보량과 속도를 연속적으로 조절**할 수 있다.
이산적 선택이 아니라 **아날로그 조절**이라는 점이 중요하다 — 마우스를 몇 도 돌릴지가 곧 실력이다.

| 숙련도 | 플레이 |
|---|---|
| 초보 | 앞만 보다 해제 타이밍을 놓치거나, 뒤를 봐서 잡힌다 |
| **숙련** | **45도로 곁눈질하며 거리를 관리하고** 정확한 순간에 시야를 끊는다 |

### FOV — 밸런스 항목이다

| FOV | 효과 |
|:--:|---|
| 60~70 | 호러 정석. 답답함 최대. **곁눈질이 거의 안 됨** |
| **75~85** | ✅ 곁눈질이 성립하면서 시야는 여전히 좁다 |
| 95+ | 곁눈질이 너무 쉬워 딜레마가 약화된다 |

**기본 80, 조절 범위 70~90.** 고정하면 멀미 민원이 발생하고,
무제한으로 열면 넓게 설정한 쪽이 유리해진다. 범위 제한이 절충점이다.

### 손전등이 포인터가 된다

> 근접 음성(§13)과 결합하면 *"저기! 저기 봐!"* + 손전등으로 비추는 동작이
> **말과 빛으로 동시에 위치를 전달**한다.
> §03의 "말로 전달해야 한다" 제약을 보조하는 비언어 채널이다.
>
> 따라서 **카메라 회전을 네트워크로 동기화해야 한다** — 남의 손전등 방향이 정보다.

### 조작 규칙 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 관측자의 "정지 3초" | **이동만 정지**, 마우스룩 허용 | 화면이 얼면 조작감 최악. 발이 묶인 채 둘러보는 게 더 무섭다 |
| 달리며 뒤 보기 | **자유롭게 허용** | 속도 손실이 페널티. 벽 충돌은 콘텐츠 |
| 목표물 운반 중 | 마우스룩 가능, **손전등 불가** | 돌아보긴 하는데 아무것도 안 보인다 |
| 청음사의 방향 판별 | **몸을 돌려 삼각측량** | 3D 오디오는 카메라 기준 → **헤드폰 필수** |

### 네트워크 동기화 항목

| 항목 | 이유 |
|---|---|
| 위치 | 기본 |
| **카메라 회전 (yaw + pitch)** | **손전등 방향 = 정보.** pitch까지 필요 — 바닥·천장을 비추는 것도 신호 |
| 손전등 on/off | 괴물 인지에 영향 |
| 운반 상태 | 애니메이션 + 속도 |
| 스태미나 (주자) | 본인만 정확히, 남은 대략 |

> **에셋 비용 — 정정**
>
> **1인칭이어도 캐릭터 모델이 필요하다.** 협동 게임에서는 다른 3명이 보여야 한다.
> 필요한 것은 **플레이어 모델 1종**(직업별 색상·소품 차이만) +
> **애니메이션 4종**(서기 / 걷기 / 달리기 / 운반) + 손전등 부착.
>
> 완화 요인: 어둡고 1인칭이라 디테일 요구가 낮고, 자기 몸은 안 보이므로 손만 있으면 된다.
> 그래도 §16-1 리스크에 포함된다.

### §06 · §12 수치에 미치는 영향

```
기존 계산:  전진 100% 가정 → 초당 0.8m 벌어짐 → 12초에 9.6m
실제:      곁눈질 95%     → 초당 0.52m       → 12초에 6.2m
```

| 항목 | 기존 | 조정 |
|---|:--:|:--:|
| 질주 최대 이동 거리 | 67m | **60m** |
| 시야 차단 지점 간격 | 15~25m | 유지 (3~4회 기회) |

**어그로 해제가 계산보다 어려워진다.** 거리를 확인하면서 도망치면 덜 벌어지기 때문이다.
최적 플레이가 어려워야 실력 여지가 생기므로 이는 바람직한 방향이다.

## 06. 괴물 — 수치와 상태 기계

### 속도 관계 — 이 한 줄이 게임 전체를 정한다

```
걷기 2.0  <  달리기 4.5  <  괴물 4.8  <  주자 질주 5.6   (m/s)
```

| 결과 | |
|---|---|
| 일반 직업은 **도망칠 수 없다** | 숨거나 정비공 · 섬광수에 의존해야 한다 |
| **주자만 도망칠 수 있다** | 직업 정체성이 수치로 확정된다 |
| 주자도 스태미나가 끝나면 잡힌다 | 무한 도주 방지 |

괴물이 달리기보다 **0.3만 빠른** 것이 핵심이다.
아주 조금 빠르면 **"거의 도망칠 수 있는데 안 되는"** 최악의 긴장이 생긴다.

> 위 값은 전진(100%) 기준이며 §05의 배율이 곱해진다. 괴물 속도는 시간대별로 변동한다(§07).

### 어그로 해제 — 거리만으로는 불가능하다

```
주자 질주 5.6 − 괴물 4.8 = 초당 0.8m 벌어짐
스태미나 12초 × 0.8      = 최대 9.6m
해제 거리 12m            → 질주만으로는 절대 못 벌린다
```

> **어그로 해제는 거리가 아니라 맵을 쓰는 것이다.**
> 모퉁이를 돌고, 문을 닫고, 구조물을 끼고 돌아야 한다. §12 맵 설계 규칙의 근거.

| 파라미터 | 1차안 | 비고 |
|---|:--:|---|
| 해제 거리 | `12 m` | |
| 시야 차단 유지 | `3 초` | 단일 모퉁이로는 부족(§12) |
| 스태미나 (질주 지속) | `12 초` | 최대 이동 60m (§05 반영) |
| 스태미나 완전 회복 | `20 초` | |
| **해제 후 괴물 행동** | — | **마지막 목격 위치로 이동 → 수색** |

> **중요:** 어그로가 풀리면 괴물은 **마지막으로 본 위치**로 향한다.
> 따라서 주자가 팀 쪽에서 어그로를 끊으면 **괴물을 팀에 배달하는 것**이 된다.
> 도망치는 *방향*이 전략이 되는 지점이며, 거리 기반 해제 설계의 핵심 대가다.

#### 주자의 진짜 딜레마 — 질주를 언제 쓸 것인가

- 처음부터 질주 → 거리는 벌지만 차단 지점 도달 전에 소진
- 아껴두면 → 그 사이에 잡힐 수 있음

**맵을 알아야 최적화된다.** 실력이 개입하는 지점이고, 그래서 반복해도 재밌다.

### 상태 기계

| 상태 | 행동 | 소리 | 전이 조건 |
|---|---|:--:|---|
| **순찰** | 경로 이동 | 발소리 | 소리 감지 → 경계 |
| **경계** | 소리 방향으로 이동 | 발소리 | 시야 확보 → 추격 / 3초 무소득 → 순찰 |
| **추격** | 직진 | 발소리+포효 | 해제 조건 충족 → 수색 |
| **수색** | 마지막 위치 반경을 뒤짐 | 발소리 | 15초 무소득 → 순찰 |
| **정지** | 멈춰서 듣는다 | **없음** | 소리 감지 → 경계 / 5초 후 → 순찰 |

> **정지 상태가 이 게임의 무기**
>
> 괴물이 멈추면 **소리를 내지 않는다.** 그러면 **청음사가 위치를 잃고**,
> 플레이어들은 *"어디 갔어? 방금 여기 있었는데"* 하게 되고, 방심하고 나오는 순간 걸린다.
>
> 순찰 중 랜덤하게(15~30초 간격) 정지를 넣는다. **침묵이 가장 무서운 소리다.**

## 07. 시간 = 위협도

> **시간이 유일한 통화다.**

모든 행동이 같은 자원을 쓰기 때문에 트레이드오프가 비교 가능해진다.

| 행동 | 비용 |
|---|:--:|
| 한 층 더 탐색 | ~3분 |
| 나가서 배터리 교체 | ~1분 |
| 전리품 하나 더 줍기 | ~40초 |
| 상점에서 고민 | ~30초 |
| 시각 확인하러 나가기 | ~1분 |

### 시간대별 위협 단계

| 경과 | 시각 | 속도 | 순찰 | 정지 | 추가 |
|:--:|---|:--:|---|:--:|---|
| 0~8분 | 초저녁 | 4.4 | 1개 구역 | 잦음 | — |
| 8~16분 | 밤 | 4.6 | 2개 구역 | 보통 | — |
| 16~24분 | 심야 | 4.8 | 절반 | 드묾 | **손전등 반경 −30%** |
| 24~32분 | 새벽 | 5.0 | 전체 | 없음 | **괴물이 출입구를 안다** |
| 32분+ | 동트기 전 | 5.2 | 전체 | 없음 | 생존 불가 수준 |

### 시각은 지상에서만 알 수 있다

안에서는 시간 감각이 없다. *"지금 몇 시쯤이야?"*를 알려면 나가야 하고, 나가는 데 시간이 든다.
이것이 또 하나의 왕복 이유가 되고, **회중시계 구매 동기**가 된다(§08).

### 왜 잠입 횟수 기반이 아니라 시간 기반인가

| 항목 | 잠입 횟수 기반 *(폐기)* | 시간 기반 *(채택)* |
|---|---|---|
| 나가서 쉬는 것 | 공짜 | **대가가 있다** |
| 압박 | 이산적 | **연속적** |
| 쇼핑 | 공짜 | **결정이 된다** |
| 구현 | 횟수 카운터 + 페널티 | **시계 하나** |

**시스템은 줄었는데 긴장은 늘었다.** 좋은 신호다.

## 08. 경제 — 전리품과 상점

### 전리품 — 무게 vs 가치

| 전리품 | 무게 | 가치 | 특징 |
|---|:--:|:--:|---|
| 은수저 · 잡동사니 | 1 | 낮음 | 눈에 잘 보임 (유혹) |
| 회중시계 · 반지 | 1 | 중간 | 효율 최고 |
| 금고 속 문서 | 2 | 높음 | 금고를 열어야 함 (정비공) |
| **대형 초상화 · 궤짝** | **5** | **매우 높음** | **2인 운반 or 극심한 감속** |

```
총 무게 5 이하  →  정상 속도
       6~10    →  −15%
       11~15   →  −30%
       16 이상  →  질주 불가 (주자도)
```

**욕심이 곧 속도 저하이고, 속도 저하가 곧 죽음이다.** §05 배율에 곱연산으로 적용된다.

> **최고의 순간:** 두 명이 궤짝을 들고 좁은 통로를 지나는데 괴물이 온다.
> 대형 전리품은 이 장면을 만들기 위해 존재한다.

### 상점 — 지상 차량, 공용 지갑

```
지상 차량 = 안전 지대 + 상점 + 보급소
전리품을 차량에 실으면 → 가치만큼 크레딧
```

> **공용 지갑이 핵심.** 크레딧은 팀 공용이다. 그래서 매번 협상이 발생한다.
>
> *"강화 손전등 하나 살까, 배터리 3개 살까?"*
> *"나 감지기 필요해. 청음사 없잖아."*
> *"아니 지금은 밧줄이 급해. 3층까지 걸어가면 5분이야."*
>
> **돈이 개인 것이면 협동 게임이 아니게 된다.**

### 성장 곡선은 판 안에서 완결된다

| 시점 | 구매력 |
|---|---|
| 1차 잠입 전 | **0** — 맨몸으로 들어간다 |
| 1차 귀환 후 | 소모품 몇 개 |
| 2~3차 귀환 후 | 강화 아이템 1개 |
| 후반 | **필요한 건 다 있는데 시간이 없다** |

**자원은 풍족해지지만 시간이 없어진다.** 성장과 압박이 반대 방향으로 움직인다.

### 구매 목록

전부 **§10 딜레마 원리**를 따른다 — 얻는 게 있으면 대가가 있다.

| 분류 | 아이템 | 효과 | 대가 |
|---|---|---|---|
| 소모품 | 배터리 | 손전등 지속 | — (기본 필수) |
| 소모품 | 정비 자재 | 문 · 함정 · 차단물 | — |
| 소모품 | 응급킷 | 부상 회복 | — |
| 탐험 | **강화 손전등** | 반경 2배 | **괴물이 2배 멀리서 본다** |
| 탐험 | 조명탄 | 구역을 밝힌다 (정비공 없이) | 1회용 · 소리를 낸다 |
| 탐험 | 분필 | 지나온 길 표시 | 괴물도 흔적을 따라온다 |
| 탐험 | 밧줄 | 층 사이 지름길 | **편도만** |
| 탐험 | 가방 | 전리품 수용 +5 | 이동 속도 −10% |
| 정보 | 건물 도면 | 맵 일부 공개 | 비쌈 |
| 정보 | **회중시계** | 안에서 시각 확인 | — |
| 정보 | 감지기 | 괴물 방향 표시 | 작동 시 소리를 낸다 |
| 위험 | 미끼 | 괴물을 특정 지점으로 유인 | 1회용 · 비쌈 |
| 위험 | **소음기** | 발소리 감소 | **자기도 못 듣게 됨 → 청음사 무효** |

**강화 손전등이 이 목록의 대표작이다** — 밝으면 더 잘 보이지만 더 잘 보인다.
**소음기는 아이템이 직업과 충돌하는 사례다** — 청음사가 있는 팀은 사면 안 된다.

### 사망자의 전리품

**떨어진다.** 회수하려면 시체가 있는 곳으로 돌아가야 한다 — 위험을 감수할 또 하나의 이유.
유령이 된 본인은 **자기 물건이 어디 있는지 보이는데 말할 수 없다**(§09).

## 09. 사망 처리 — 유령

| 항목 | 유령 상태 |
|---|---|
| 시야 | **맵 전체를 자유롭게 본다** (벽 통과) |
| 말하기 | **불가능** |
| 신호 | 근처 물건을 아주 약하게 흔든다 (쿨타임 45초) |
| 탈출 | **불가능** — 사망 페널티가 명확해진다 |

| 문제 | 해결 |
|---|---|
| 죽으면 지루하다 | 볼 게 있고 할 게 있다 |
| 죽은 사람이 정보를 주면 밸런스 붕괴 | **말할 수 없다** → 자유 정보 제공 불가 |
| 폐기한 영매 구조(§15) | **직업이 아니라 사망 후 상태로 재활용** |

영매가 직업으로 실패한 이유는 *"아무도 하고 싶어하지 않는다"*였다.
**벌칙 상태로 옮기면 그 문제가 사라진다** — 선택하는 게 아니니까.

> **최고의 순간**
>
> 산 자가 잘못된 길로 가고 있는데 유령은 정답을 안다. 그런데 **말할 수 없다.**
> 물건을 흔들어 신호를 보낸다. 쿨타임 45초 안에 다시 시도할 수 없다.
>
> *"방금 뭔가 흔들렸어?" / "바람이겠지" / (유령의 절규)*

## 10. 딜레마 지도

> **얻으려면 위험을 만들어야 한다.**

| 주체 | 얻는 것 | 대가 |
|---|---|---|
| 누구나 | 단서를 읽는다 | 위험 구역에 있어야 한다 |
| 누구나 | 손전등을 켠다 | 괴물이 본다 · 배터리를 쓴다 |
| 누구나 | 전리품을 챙긴다 | 시간을 쓰고 느려진다 |
| 누구나 | 목표물을 든다 | 손전등을 못 든다 · 질주 불가 |
| **도망 중** | **뒤를 봐서 거리를 확인한다** | **속도 65% → 거리가 좁혀진다** (§05) |
| 팀 전체 | 나가서 쉰다 · 구매한다 | 시간이 흐른다 |
| 정비공 | 구역을 밝힌다 | 괴물이 그쪽으로 온다 |
| 정비공 | 경로를 차단한다 | 아군도 막힌다 |
| 청음사 | 소리를 듣는다 | 자기가 조용해야 한다 |
| 관측자 | 괴물의 시야를 본다 | 15m 이내에서 3초 정지해야 한다 |
| 주자 | 진입 창을 만든다 | 팀에서 분리된다 |
| 구매 | 강화 손전등 | 괴물이 2배 멀리서 본다 |
| 구매 | 소음기 | 청음사가 무효화된다 |

하나의 원리 위에 전부 올라가 있다. 덕분에 **튜토리얼이 한 줄로 끝나고**,
새 콘텐츠를 추가할 때 **채택 기준이 명확하다** — *"이 기능은 이득과 위험을 교환하는가?"*

## 11. 인원 구조

**4인 플레이 + 5개 중 4개 선택.** 매판 하나가 빠지고, 그게 그 판의 성격이 된다.

| 빠진 직업 | 그 판의 난제 | 돈으로 메우기 |
|---|---|---|
| 청음사 | 괴물의 위치를 모른다 — **공포 최대** | **감지기** (소리를 낸다) |
| 관측자 | 누가 표적인지 모른다 | **불가능** |
| 주자 | 괴물을 끌 수 없다 | **미끼** (위치를 미리 정해야) |
| 정비공 | 단서 읽기가 훨씬 위험해진다 | **조명탄** (1회용, 구역 하나) |
| 섬광수 | 저지 수단이 없다 | **섬광탄** (소모품, 수량 제한) |

> **경제 시스템의 부수 이득**
>
> §08의 구매 시스템이 **"필수 직업 금지" 원칙을 훨씬 튼튼하게 만든다.**
> 약점을 돈으로 메울 수 있게 되면서 조합의 다양성이 실제로 성립하고,
> 전부 *열등한 대체재*이므로 직업의 가치는 유지된다.
>
> **관측자만 대체 수단이 없다** — 유일하게 *살 수 없는 정보*를 제공하는 직업이다.

> **절대 규칙: 필수 직업이 있으면 풀이 가짜가 된다.**
>
> 정비공 없이 게임이 불가능하면 실제 선택지는 없고 매판 같은 조합만 고른다.
> 그래서 **손전등을 전원 기본 지급**했다 — 정비공은 *효율*이지 *자격*이 아니다.

**검증법:** 5가지 조합을 전부 돌려본다.
성립하지 않는 조합이 하나라도 있으면 그 직업이 과하게 필수적이다.

## 12. 맵 설계 규칙

> **맵은 아트가 아니라 시스템이다.**
> §06의 수치가 맵의 **성립 조건**을 규정한다. 아래는 수치에서 역산한 규칙이다.

### 가장 중요한 계산 — 단일 모퉁이는 실패한다

```
주자가 모퉁이 통과 시점의 거리 = D
괴물이 그 모퉁이에 도달하는 시간 = D / 4.8초
시야 차단 3초가 필요 → D ≥ 14.4m

질주로 벌 수 있는 거리 = (5.6 − 4.8) × 12초 = 9.6m  (전진 기준)
```

| 어그로 시작 거리 | 모퉁이 통과 시 거리 | 판정 |
|:--:|:--:|:--:|
| 3m | 12.6m | ❌ 실패 |
| 5m | 14.6m | ⚠️ 이론상 겨우 |
| **10m** | **19.6m** | ✅ 여유 |
| 15m | 24.6m | ✅ 안정 |

**결론 두 개.**
1. 주자는 **멀리서 어그로를 걸어야 한다.**
2. 단일 모퉁이에 의존하면 안 된다 — 안정적 해제에는 **연속 차단**이 필요하다.

### 연속 차단 구조 3종

#### ① S자 통로 ← 가장 확실

```
────┐
    │  ← 구간 L
    └────┐
         │  ← 구간 L
         └────

구간 L = 10m,  총 20m
통과 시간 = 20 / 4.8 = 4.2초  ≥  3초  ✅
```

**10m 구간 2개의 S자 통로 하나면 해제가 성립한다.** 이것이 맵의 기본 단위다.

#### ② 순환로
돌아서 반대편으로 나올 수 있는 구조. 괴물이 **어느 방향인지 추측해야** 한다.

#### ③ 분기
갈림길. 괴물이 잘못 고르면 완전히 놓치지만 확률적이라 신뢰도가 낮다 — 보조 수단으로만.

### 두 성격의 공간이 인접해야 한다

| 공간 | 역할 | 특성 |
|---|---|---|
| **개방 공간** | **멀리서 어그로를 건다** | 홀 · 마당 · 계단실. 시야 15~25m 확보 |
| **미로 공간** | **시야를 끊고 도망친다** | S자 통로 · 순환로 · 좁은 복도 |

```
[개방 공간] ──진입── [미로 공간]
   어그로 획득          어그로 해제
```

개방 공간만 있으면 도망칠 곳이 없고, 미로만 있으면 멀리서 어그로를 걸 수 없다.

### 수치 규칙

| 항목 | 규칙 | 근거 |
|---|:--:|---|
| 시야 차단 지점 간격 | `15~25m` | 질주 60m에 3~4번의 기회 |
| S자 통로 구간 | `10m × 2회 굽음` | 통과 4.2초 > 차단 3초 |
| 순환로 개수 | 구역당 1+, 전체 3+ | 트리 구조는 사형선고 |
| 막힌 길 비율 | `20~25%` | 적으면 맵 지식 무의미, 많으면 운에 죽음 |
| 막힌 길 보상 | 전리품 · 자재 | 위험을 감수할 이유 |
| 구역 개수 | `4~6` | 단서 + 목표물 후보 + 출구 |
| 구역 대각선 | `30~40m` | |
| 맵 전체 | `100 × 100m` | 주자가 구역 2~3개 관통 가능 |
| 구역 간 진입점 | `2~3` | §07 순찰 반경이 구역 단위로 성립해야 |
| **직선 통로 최대** | **`20m`** | **넘으면 주자가 죽는다** |

### 직업별 맵 요구조건

#### 청음사 → 바닥 재질이 지도다

| 구역 | 바닥 | 발소리 |
|:--:|---|---|
| A | 나무 | 삐걱 |
| B | 타일 | 딱딱, 반향 |
| C | 자갈 | 부스럭 |
| D | 콘크리트 | 둔탁 |
| 계단 | 금속 | 울림 |

**구역별로 바닥 재질이 달라야 청음사가 위치를 판별할 수 있다.**
아트 결정이 아니라 **시스템 결정**이다. 재질 경계를 명확히 할 것.

#### 관측자 → 관측 지점
높이 차(2층 난간) · 창문 · 격자 등 **15m 거리에서 안전하게 괴물을 볼 수 있는 지점**을
**구역당 1~2개** 배치. 없으면 관측자는 죽으러 가야 한다.

#### 정비공 → 병목에 문
- 순환로의 목에 문 하나 → 잠그면 순환이 끊김 (전략적 선택)
- **구역당 잠글 수 있는 문 1~2개** — 많으면 정비공이 만능이 된다
- 전기 패널 구역당 1개

#### 섬광수 → 좁은 공간
넓은 곳에서는 괴물이 우회한다. 미로 공간이 무대이므로 별도 요구조건은 없다.

### 단서 · 목표물 후보 지점 조건

| 조건 | 이유 |
|---|---|
| **탈출로 2개 이상** | 하나 막히면 다른 쪽 |
| 각 입구에서 내부가 안 보임 | 괴물이 지나가도 즉시 발각 안 됨 |
| 근처에 시야 차단 지점 | 발각되면 즉시 도망 가능 |
| 전기 패널 접근 가능 | 정비공이 밝힐 수 있어야 |

**후보 지점을 구역당 3개씩** 만들어두고 그중 하나를 선택한다.
**모든 후보가** 위 조건을 만족해야 한다.

### 검증 체크리스트

- [ ] 20m 넘는 직선 통로가 없다
- [ ] 개방 공간이 최소 1개 있고, 미로 공간과 인접해 있다
- [ ] S자 통로(10m×2)가 구역당 최소 1개 있다
- [ ] 순환로가 맵 전체에 3개 이상 있다
- [ ] 막힌 길 비율이 20~25%이고, 각각 보상이 있다
- [ ] 구역별 바닥 재질이 다르고 경계가 명확하다
- [ ] 관측 지점이 구역당 1개 이상 있다
- [ ] 잠글 수 있는 문이 구역당 1~2개, 병목에 있다
- [ ] 단서·목표물 후보가 구역당 3개, 모두 탈출로 2개 이상
- [ ] 구역 간 진입점이 2~3개로 제한돼 있다
- [ ] 출입구 근처에 은폐 지점이 있다 (§07 새벽 단계 대응)

### 실전 검증 — 주자 테스트

**맵의 임의 지점에서 어그로를 걸고, 해제할 수 있는가?** 10개 지점에서 시도한다.

| 성공률 | 판정 |
|:--:|---|
| 8/10 이상 | ⚠️ 너무 쉽다 — 시야 차단 지점을 줄인다 |
| **5~7/10** | ✅ **적정** |
| 3/10 이하 | ⚠️ 너무 어렵다 — S자 통로를 추가한다 |

### 첫 맵 스케치

```
        ┌──────────────┐
        │   B 타일      │  ← 개방 공간 (홀), 시야 20m
        │  [관측지점]    │
        └───┬──────┬───┘
      S자통로│      │순환로
        ┌───┴──┐ ┌─┴────┐
        │A 나무 │ │C 자갈 │
        │[단서] │ │[단서] │
        └───┬──┘ └──┬───┘
            │  [문]  │      ← 정비공 병목
        ┌───┴───────┴───┐
        │   D 콘크리트    │
        │   [출구]        │
        └────────────────┘
```

프로토타입은 **B + A + S자 통로**만 만들면 된다.

## 13. 인프라와 기술 스택

> **직접 띄울 서버가 0대. DB도 필요 없다. 월 고정비 0원, 초기 비용 $100.**
>
> 4인 P2P + 호스트 권한 구조에서는 "서버"가 곧 플레이어 PC이므로 Steam이 나머지를 전부 제공한다.

### Steam이 무료로 주는 것

| 기능 | Steamworks | 비용 |
|---|---|:--:|
| **P2P 네트워킹** | Steam Networking Sockets | 0 |
| **NAT 통과 + 릴레이** | Steam Datagram Relay (SDR) | 0 |
| 로비 / 친구 초대 | ISteamMatchmaking | 0 |
| **음성 캡처 + 코덱** | ISteamUser::GetVoice | 0 |
| 계정 / 신원 | Steam ID | 0 |
| 세이브 | Steam Cloud | 0 |
| 업적 · 통계 · 리더보드 | Steam Stats / Leaderboards | 0 |
| 배포 · 패치 | Depot upload (steamcmd) | 0 |

**릴레이가 무료인 것이 결정적이다.** NAT 뒤의 플레이어끼리 직접 연결이 안 될 때
트래픽을 중계해야 하는데, 직접 하면 대역폭 요금이 실제로 나간다.

따라서 **전용 서버 · 매칭 서버 · 릴레이 서버 · 계정 서버 · DB 전부 불필요하다.**

### DB가 필요할 것 같은 것들

| 필요해 보이는 것 | 실제 해법 | DB |
|---|---|:--:|
| 계정 · 프로필 | Steam ID | ❌ |
| 세이브 | Steam Cloud | ❌ |
| 리더보드 | Steam Leaderboards | ❌ |
| 매칭 · 방 목록 | Steam Lobbies | ❌ |
| 업적 · 통계 | Steam Stats | ❌ |
| **영구 진행도 · 인벤토리** | **없음 — §08에서 판 안에 완결됨** | ❌ |

마지막 항목이 중요하다. **§15에서 판 사이 메타 프로그레션을 폐기한 것이
인프라 이득으로 돌아온다.** 영구 진행도가 있으면 저장해야 하고, 저장하면 치팅 검증이
필요해지고, 그러면 진짜 서버가 필요해진다.

### 착각하기 쉬운 것들 — 이것도 서버 불필요

| 하고 싶은 것 | 방법 |
|---|---|
| 게임 내 공지 | Steam 뉴스 API, 또는 정적 JSON 파일 |
| 구버전 접속 차단 | Steam이 자동 업데이트를 강제 → 대부분 자동 해결 |
| 웹사이트 | **스팀 페이지가 랜딩.** 프레스킷만 정적 호스팅(무료) |
| 커뮤니티 | Discord — Discord가 호스팅 |
| 빌드 자동화 | GitHub Actions (선택). 초기엔 수동 `steamcmd` |

### 근접 음성 구현

```
① 마이크 캡처       →  ISteamUser::GetVoice()
② 압축 패킷 전송     →  Steam Networking (P2P)
③ 수신 후 압축해제   →  DecompressVoice()
④ 재생             →  송신자 캐릭터 위치의 3D 오디오 소스로
```

> **핵심 트릭: 음성을 3D 오디오 소스로 재생하면 근접 음성이 자동으로 된다.**
> 거리 계산 로직이 필요 없다. 엔진의 3D 오디오가 감쇠와 벽 차폐를 처리한다.

```
거리 > 30m  →  전송 자체를 중단
```

**전부 받아놓고 볼륨만 0으로 재생하면 클라이언트 조작으로 다 들린다.**
전송 단계에서 끊어야 한다 — 대역폭 절감보다 **도청 방지**가 본질이다.
대역폭은 압축 후 초당 2~8KB 수준으로 부담이 없다.

### 텔레메트리 — 3단계, DB 없음

§06 수치는 **실제 사람들 데이터 없이는 못 맞춘다.** 하지만 요구사항을 보면
`판 종료 시 요약 1건 전송 → 나중에 집계` 로, **append-only 로그**다.
트랜잭션 · 조인 · 인덱스 · 실시간 쿼리가 전부 불필요하다.

#### 1단계: Steam Stats만 (인프라 0)

통계 항목을 정의하면 Steam이 저장하고 글로벌 집계까지 해준다.
**분포가 필요하면 버킷 카운터를 만든다.**

```
aggro_duration_0_5s     : 카운터
aggro_duration_5_10s    : 카운터
aggro_duration_10_15s   : 카운터
aggro_duration_15s_plus : 카운터
```

**히스토그램이 Steam Stats만으로 나온다.** 같은 방식으로:

| 버킷 | 검증 대상 |
|---|---|
| 어그로 지속 시간 | §06 해제 거리 12m |
| 왕복 횟수 | §07 시간 곡선 |
| 후진(S) 사용 시간 비율 | §05 곁눈질 배율 65% |
| 직업별 선택 카운터 5개 | §11 필수 직업 검증 |
| 아이템별 구매 카운터 | §08 경제 밸런스 |
| 클리어 / 전멸 / 포기 | 전체 밸런스 |

**밸런싱에 필요한 거의 전부가 여기서 나온다.**

#### 2단계: 로그 파일 (세부 이벤트가 필요해지면)

사망 좌표처럼 세부 데이터가 필요해지면:

```
서버리스 함수 1개  →  오브젝트 스토리지에 JSONL append
                     (S3 / R2 / Blob)
```

**DB가 아니라 파일이 쌓인다.** 나중에 다운로드해서 로컬 DuckDB로 쿼리한다
(JSONL / Parquet 직접 읽기 가능). 스키마 · 마이그레이션 · 백업 · 커넥션 전부 없음.

#### 3단계: 분석 서비스 (규모가 커지면)

PostHog 등을 붙인다. 이때도 DB는 서비스가 관리하고 나는 이벤트만 쏜다.

> 익명 세션 ID만 쓴다. **개인정보는 수집하지 않는다.**

### 기술 스택 (Unity)

| 영역 | 선택 | 근거 |
|---|---|---|
| 엔진 | **Unity** | 네트워킹 + 3D 오디오 + Steam 연동 생태계가 가장 성숙 |
| 1인칭 컨트롤러 | Starter Assets 또는 직접 | 마우스룩은 스크립트 20줄 수준 |
| Steamworks | Steamworks.NET | 저수준 래퍼, 안정적, 무료 |
| 네트워킹 | **Mirror + FizzySteamworks** | 자료·커뮤니티 최다 — **막혔을 때 검색이 된다** |
| 대안 | FishNet + FishySteamworks | 성능·기능은 앞서지만 자료가 적다 |
| 오디오 | Unity 기본 → 필요시 FMOD | 청음사 판별 가능 여부를 프로토타입에서 판정 |
| 개발용 App ID | `480` (Spacewar) | 심사 전에도 로비·P2P·음성 테스트 가능 |

성능 차이보다 **막혔을 때 답을 찾을 수 있는지**가 1인 개발에서 훨씬 중요하다.
4인 게임에서 성능 한계에 부딪힐 일은 없다.

### 아키텍처 — 호스트 권한

| 항목 | 결정 |
|---|---|
| 권한 모델 | **호스트 권한** — 괴물 AI를 호스트가 돌린다 |
| 치팅 방어 | 거의 불필요 (친구끼리 하는 PvE) |
| 호스트 이탈 | **세션 종료** — 마이그레이션 하지 않음 |
| **단서 내용 · 목표물 위치** | **호스트만 보유.** 클라이언트에 보내면 메모리에서 읽힌다 |

마지막 항목이 중요하다. 정답을 클라이언트에 전송하면
**§03의 "기억해서 말로 전달" 제약이 무너진다.**

### 인프라가 아니라 행정 — 세팅해야 할 것

| 항목 | 비고 |
|---|---|
| Steamworks 파트너 등록 | 사업자 정보 · 은행 계좌 |
| **App ID** | **$100** (매출 $1,000 초과 시 환급) |
| W-8BEN 제출 | 한미조세조약으로 원천징수 감면 |
| Depot 설정 + 업로드 | 초기엔 수동 `steamcmd`로 충분 |
| **상점 페이지 자산** | 캡슐 이미지 · 트레일러 · 스크린샷 — **시간이 꽤 든다** |
| 헤드폰 권장 표기 | §05 — 3D 오디오가 게임의 핵심 |

### 나중에 서버가 필요해질 수 있는 경우

| 상황 | 필요해지는 것 |
|---|---|
| 스팀 외 플랫폼 출시 (에픽 등) | 자체 매칭 · 음성 추상화 레이어 |
| 공개 매칭 (친구 아닌 사람과) | Steam Lobbies로 가능하나 신고 · 필터 시스템 |
| 커뮤니티 데디케이티드 서버 요구 | 전용 서버 빌드 |

전부 지금은 불필요하다. 다만 **음성 · 네트워킹을 인터페이스로 추상화**해두면
나중 확장 비용이 줄어든다. 코드 몇 줄 차이다.

### 2주 프로토타입

**만들 것**
- 구역 3개 (수작업, §12 스케치의 B+A)
- **1인칭 이동 + 속도 배율표**
- 단서 2개 + 목표물 1개
- 직업 2개: **주자 + 정비공**
- 괴물 1마리, 어그로 + 상태 기계
- 시계 + 시간대별 위협 2단계
- 전리품 3종 + 무게 규칙
- 2인 로컬 (캐릭터는 **캡슐**)

**안 만들 것**
- 랜덤 생성
- 나머지 직업 3개
- 게임 내 음성
- 상점 (전리품만 확인)
- 캐릭터 모델 · 애니메이션
- 매칭 · 로비 · 세이브
- 아트 · 사운드 폴리시 · 유령 상태

### 검증 질문 — 이 다섯 개만

| # | 질문 | 실패 시 |
|:--:|---|---|
| 1 | **추격이 재밌는가?** (거리를 벌리는 순간이 짜릿한가) | §06 어그로 수치를 고친다 |
| 2 | **곁눈질 딜레마가 작동하는가?** (뒤를 볼지 고민하게 되는가) | §05 후진 배율(65%)을 조정 |

## 15. 설계 이력

이 설계에 도달하기까지 버린 것들. 되돌아가지 않기 위해 기록한다.

| 폐기안 | 폐기 이유 |
|---|---|
| 런타임 LLM 활용 | 매절 판매 + 변동비 = 잘 팔릴수록 적자. 지연시간도 실시간 액션과 맞지 않음 |
| 영매 / 침식 구조 *(감각 비대칭)* | 화면이 검은 역할은 **아무도 하고 싶어하지 않는다.** 감각을 대칭으로, 능력만 비대칭으로. 단 §09에서 사망 상태로 회수됨 |
| 사수 (총기 직업) | 괴물을 죽일 수 있으면 공포가 사라진다. 저지는 전부 일시적이어야 함 |
| 해독가 (목표 전담) | 목표를 한 명이 담당하면 나머지는 호위병이 된다. 전원 공동 작업으로 |
| 의무병 / 서포터 | 필수인데 재미없는 역할. 회복은 **직업이 아니라 아이템**으로 |
| 시간 기반 어그로 해제 | 기다리는 것은 실력이 아니다. 거리 + 시야 차단으로 대체 |
| 적응형 보스 패턴 | 고무줄 효과로 실력 성장의 보상이 사라진다. 대신 랜덤화 + 시간 기반 위협(§07) |
| 의식 복원 (목표 구조) | **서사 장치라 반복하면 빨리 낡는다.** 왕복 + 목표물 회수로 대체 |
| 잠입 횟수 기반 위협도 | 나가서 쉬는 것이 공짜가 되고 인공적 카운터가 필요. **시간 기반이 더 단순하고 압박이 연속적** |
| "벽에 부딪힌다"는 뒤보기 페널티 | 애매한 서술. **후진 속도 65%라는 수치로 대체**(§05) |
| 전용 서버 / 자체 릴레이 | Steam SDR이 무료로 해준다. 1인 개발자가 감당할 영역이 아님 |
| **텔레메트리용 DB (Supabase 등)** | **append-only 로그에 DB는 과하다.** Steam Stats 버킷 → JSONL → 서비스 순으로 |
| 판 사이 메타 프로그레션 | 한 판 25~35분 안에 성장 곡선이 완결된다(§08). 나중에 추가 가능 |

> **설계 관통 원칙**
>
> **패턴은 학습하게 두고, 내용을 매번 바꾼다.**
> 구조를 배우는 것이 실력이고, 그 실력이 통하지 않게 만들면 게임이 죽는다.
> 공략을 막으려 하지 말고, **공략을 봐도 남에게 전이되지 않는 축**을 만들 것.

> **1번 리스크 — 범위가 늘었다**
>
> §05에서 확인된 대로 **1인칭이어도 캐릭터 모델이 필요하다** (협동이라 남이 보인다).
> 괴물 1종 + 플레이어 1종 + 애니메이션. 나머지는 1인칭 · 어둠 · 모듈러로 우회 가능하지만
> **이 둘은 우회가 안 된다.** 프로토타입에서는 캡슐로 대체하고
> **에셋스토어를 미리 조사해 둘 것.** 없으면 일정이 몇 달 늘어난다.

> **2번이 현재 병목**
>
> **전리품 가치와 아이템 가격의 비율**이 게임 템포를 결정한다.
> 너무 싸면 2차 잠입에 다 갖춰지고, 너무 비싸면 아무것도 못 산다.
> §08의 성장 곡선(*1차 0 → 후반 자원 풍족 · 시간 부족*)이 실제로 나오는지가 판정 기준이다.
